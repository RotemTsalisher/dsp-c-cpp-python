Amdahl's Law

If fraction p of execution time is sped up by factor s:

Speedup = 1 / ((1 − p) + p/s)

The lesson: optimizing a tiny part of the application has a hard ceiling.

Exercise 9.1

A program spends 70% in one kernel. You make that kernel 5× faster. What is total speedup?

Speedup = 1 / (0.30 + 0.70/5) = 1 / 0.44 ≈ 2.27×. Even a 5× kernel improvement cannot produce 5× application speedup because the remaining 30% is unchanged.

Exercise 9.2

A 90% hot region is improved 10×. What is total speedup? What is the asymptotic maximum if that region became infinitely fast?

10×: 1/(0.10+0.90/10)=1/0.19≈5.26×. Infinite speedup of the hot region gives 1/0.10 = 10× maximum.

Exercise 9.3

A kernel needs 1.2 million cycles per second of work. The DSP runs at 600 MHz. What fraction of one core's compute capacity is that, assuming one cycle can execute the required work?

1.2M / 600M = 0.2%. But this simplistic calculation is only meaningful if “one cycle can execute the required work” matches the actual instruction/issue model. In a real DSP you must account for instruction throughput, vector width, memory stalls, dependencies, and other workloads.

Exercise 9.4

A loop performs 8 loads and 8 multiplies per output. If each load is 4 bytes, how many bytes/output are read? What additional information is needed to decide if it is memory-bound?

32 bytes of input/coeff data per output if all eight loads are unique and 4 bytes each. To judge memory-bound behavior you need cache reuse, stores, actual memory hierarchy, attainable bandwidth, instruction throughput, and the target architecture. Raw bytes alone are insufficient.

Exercise 9.5

You reduce runtime from 10 ms to 8 ms. What percentage improvement is that? What is the speedup?

Runtime reduction = (10−8)/10 = 20%. Speedup = 10/8 = 1.25×. These are different statements and both should be reported correctly.

Exercise 9.6

A benchmark says 1000 cycles. Another says 1.7 µs. Can you infer CPU frequency? If yes, how?

Yes if the measurements refer to the same execution: frequency = cycles/time = 1000 / 1.7µs ≈ 588.2 MHz. In practice verify whether cycle count and wall time include the same region and whether clock frequency is fixed or dynamically changing.

Exercise 9.7

Explain why optimizing for average latency can be insufficient in a hard real-time system.

Averages hide tails. A system that usually finishes in 1 ms but occasionally takes 4 ms can still miss a 2 ms deadline. Real-time analysis must consider bounded/worst-case behavior, jitter, scheduling, interrupts, contention, and system-level deadlines.

Exercise 9.8

Design a benchmark for a DSP kernel that avoids measuring startup/cache warm-up instead of steady-state performance.
  1. Define input sizes and representative data.
  2. Warm up the kernel if appropriate.
  3. Run many iterations.
  4. Measure a sufficiently large region to reduce timer noise.
  5. Report distribution, not only one number.
  6. Control CPU frequency/environment where possible.
  7. Check compiler flags and build configuration.
  8. Validate outputs so the benchmark cannot accidentally optimize away work.
