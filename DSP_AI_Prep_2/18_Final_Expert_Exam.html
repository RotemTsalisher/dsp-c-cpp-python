Exercise 18.1

C/C++ A function receives two float pointers and a length. Explain all assumptions required to safely vectorize it, including aliasing, bounds, alignment, and tail handling.

A safe answer mentions valid ranges, non-overlap if required, object lifetime/type, alignment strategy, n bounds, vector width/tail, numerical tolerance, and compiler/ISA assumptions.

Exercise 18.2

DSP Design a 96-tap low-pass FIR for a 48 kHz signal. Explain implementation, computational load, and how you would validate it.

Discuss coefficient design, sampling specs, 96 MACs/output, 4.608M multiplications/s for 48k outputs if 96 taps/output, frequency response validation, impulse/step tests, numerical reference and performance.

Exercise 18.3

Fixed point Convert the conceptual FIR to fixed point. What must be specified before coding?

Input/coeff ranges, Q formats, accumulator width, headroom, rounding, saturation, output scaling, coefficient quantization and error tolerance.

Exercise 18.4

SIMD Propose two SIMD strategies for the FIR and discuss when each is preferable.

Vectorize across taps for one output or across multiple outputs/samples depending on layout. Discuss reuse, alignment, coefficient broadcasting, boundary handling and throughput.

Exercise 18.5

Real time The block size is 96 samples at 48 kHz. Calculate block period and explain what margin means.

96/48000=2 ms. Margin is deadline minus worst-case processing/scheduling overhead; average alone is insufficient.

Exercise 18.6

Profiling The FIR uses only 20% CPU but misses deadlines. What does that suggest?

Potential scheduling/jitter, memory stalls, contention, other pipeline stages, blocking, I/O/DMA, priority issues, or incorrect utilization measurement. Investigate the complete path.

Exercise 18.7

Communications A QPSK receiver shows a rotating constellation and high BER. Diagnose systematically.

Frequency offset causes phase rotation; estimate/correct carrier offset, then check timing, phase ambiguity, filtering, scaling and BER.

Exercise 18.8

ML A quantized neural-network model is 2× smaller but only 5% faster. Explain possible reasons and optimization plan.

Memory footprint reduction does not guarantee compute speedup. Check kernels, conversions, layout, bandwidth, operator fusion, hardware support and dispatch overhead.

Exercise 18.9

System design You must meet a 2 ms hard deadline and reduce power by 20%. How do you optimize?

Measure both latency and power; identify bottlenecks; consider memory movement, frequency, vectorization, batching constraints, algorithmic changes, and workload scheduling; validate worst-case latency and energy.

Exercise 18.10

Leadership A teammate claims your optimization is wrong; your benchmark says it is faster but their correctness test fails. What do you do?

Reproduce both results, compare reference definitions/tolerances, isolate the numerical discrepancy, determine whether the optimization violates a requirement, and resolve using evidence rather than authority.
