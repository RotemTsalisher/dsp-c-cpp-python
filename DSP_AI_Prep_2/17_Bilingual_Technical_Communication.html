Exercise 17.1

What is cache locality?

English target

Cache locality means structuring memory accesses so the processor can reuse recently loaded data and nearby data efficiently. Temporal locality is reuse over time; spatial locality is access to nearby addresses.

עברית

Cache locality הוא תכנון גישות לזיכרון כך שהמעבד יוכל לנצל נתונים שכבר נטענו ונתונים שנמצאים בקרבתם. Temporal locality היא שימוש חוזר בנתון, ו-spatial locality היא גישה לכתובות סמוכות.

English:

Cache locality means structuring memory accesses so the processor can reuse recently loaded data and nearby data efficiently. Temporal locality is reuse over time; spatial locality is access to nearby addresses.

עברית:

Cache locality הוא תכנון גישות לזיכרון כך שהמעבד יוכל לנצל נתונים שכבר נטענו ונתונים שנמצאים בקרבתם. Temporal locality היא שימוש חוזר בנתון, ו-spatial locality היא גישה לכתובות סמוכות.

Exercise 17.6

Hard oral: Explain why a vectorized implementation may be faster but numerically different.
English model:

Vectorization can change the order in which floating-point operations are performed. Because floating-point addition is not perfectly associative, the optimized reduction may produce slightly different rounding. I would accept it only if the numerical difference is inside the defined tolerance and does not create downstream instability.

עברית:

Vectorization יכולה לשנות את סדר הפעולות החשבוניות. מכיוון שחיבור floating-point אינו אסוציאטיבי לחלוטין, שינוי הסדר משנה rounding. אקבל את המימוש רק אם השגיאה עומדת ב-tolerance שהוגדר ולא יוצרת בעיה בהמשך ה-pipeline.

Exercise 17.7

Hard oral: “The code is already optimized. Why is it still missing the deadline?” Answer as an engineer, not as a student.

English model: “I would first verify the deadline measurement and reproduce the miss. Then I would profile the complete real-time path, including memory movement, synchronization, interrupts and scheduling—not just the kernel. The issue may be system-level rather than local compute. I would identify the dominant contributor, quantify the required margin, and evaluate architectural changes if local optimization is insufficient.”

עברית: “קודם אאמת שה-deadline והמדידה נכונים ואשחזר את הבעיה. לאחר מכן אעשה profiling לכל ה-real-time path, כולל memory movement, synchronization, interrupts ו-scheduling, ולא רק ל-kernel. יכול להיות שהבעיה מערכתית ולא מקומית. אזהה את הגורם הדומיננטי, אחשב את ה-margin הנדרש, ואם אופטימיזציה מקומית לא מספיקה אשקול שינוי ארכיטקטוני.”
