Exercise 12.1

Why might a DSP be attractive for repeated MAC-heavy workloads?

A DSP architecture can be designed around efficient signal-processing operations, predictable data movement, vectorization, specialized addressing, and deterministic real-time execution patterns. The exact advantage depends on the target DSP and workload; avoid assuming every DSP beats every CPU.

Exercise 12.2

Why might a GPU be excellent for a large neural-network workload but unsuitable for a tiny latency-critical kernel?

Large workloads can expose massive parallelism and amortize dispatch/data-transfer overhead. A tiny kernel may not have enough parallel work to occupy the GPU, and launch/transfer overhead can dominate latency. Again, architecture and workload matter.

Exercise 12.3

A kernel has perfect arithmetic parallelism but random memory accesses. What does that tell you?

Compute parallelism does not guarantee performance. Random accesses can destroy locality, increase cache misses, reduce memory coalescing/vector efficiency, and make memory latency/bandwidth the dominant constraint.

Exercise 12.4

Explain the difference between latency hiding and latency reduction.

Latency reduction makes an individual operation complete sooner. Latency hiding keeps useful work executing while another operation waits, for example overlapping independent computation with memory operations. A system can have high individual latency but good throughput if it hides that latency effectively.

Exercise 12.5

A compiler-generated assembly looks more complicated after -O3 than your hand-written loop. Is that automatically bad?

No. Optimizers may unroll, vectorize, schedule, eliminate bounds checks, use fused operations, and transform control flow. The correct test is generated-code quality plus measured behavior and correctness—not visual simplicity of assembly.

Exercise 12.6

What would you inspect in assembly for a hot FIR kernel?
  • Vector instructions and vector width.
  • Load/store count and addressing patterns.
  • Multiply/FMA usage.
  • Dependency chains.
  • Loop branches and unrolling.
  • Register pressure/spills.
  • Alignment assumptions.
  • Unexpected calls or conversions.
  • Instructions indicating poor type/precision handling.
