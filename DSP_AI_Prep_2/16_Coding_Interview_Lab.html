Exercise 16.1

Implement memmove-style copying for overlapping ranges. Explain why copying direction matters.

If destination starts after source and ranges overlap, copy from the end toward the beginning; otherwise copy forward. The direction prevents overwriting source bytes before they are read.

void move_bytes(unsigned char* d,const unsigned char* s,size_t n){
    if(d==s || n==0) return;
    if(d < s){
        for(size_t i=0;i<n;i++) d[i]=s[i];
    } else {
        for(size_t i=n;i>0;i--) d[i-1]=s[i-1];
    }
}

Exercise 16.2

Implement a ring buffer for fixed-size float samples. Define full/empty semantics and make all boundary conditions explicit.

A good solution uses storage + read index + write index + count, or a one-empty-slot convention. The important part is defining the invariant. For example: 0≤count≤capacity; write increments modulo capacity; read increments modulo capacity. In a concurrent embedded system, synchronization/atomicity becomes another design dimension.

Exercise 16.3

Implement a moving average of length N in O(1) work per new sample instead of summing N samples every time.

Maintain a running sum and a circular buffer. For each new sample: subtract the outgoing sample, add the incoming sample, store it, advance the index, divide by N. Complexity becomes O(1) per sample, with O(N) storage.

Exercise 16.4

Why can the moving-average optimization introduce fixed-point issues?

The running sum has a larger dynamic range than an individual sample. It can overflow if stored in the same width. Also, division by N may require scaling/rounding. Choose accumulator width based on worst-case sum and define saturation/rounding.

Exercise 16.5

Implement a function that finds the maximum absolute value of an int16 array without overflowing when negating INT16_MIN.

-INT16_MIN cannot be represented in int16. Convert to a wider signed type before taking absolute value.

int16_t max_abs(const int16_t* x,size_t n){
    int32_t best=0;
    for(size_t i=0;i<n;i++){
        int32_t v=x[i];
        if(v<0) v=-v;
        if(v>best) best=v;
    }
    return (int16_t)best; // only safe if caller accepts that max abs may be 32768
}

For a truly correct API, return int32_t because 32768 cannot fit in int16_t.

Exercise 16.6

Implement a dot product using two accumulators and explain what changes if the function is compiled with aggressive floating-point reassociation.

Use two independent accumulators over alternating elements or chunks. Reassociation can change rounding compared with the scalar left-to-right sum. The output should therefore be validated against a defined tolerance rather than assumed bit-identical.

Exercise 16.7

You are given an array of interleaved complex samples [I0,Q0,I1,Q1,...]. Write the magnitude-squared sequence without computing square roots.
for(size_t k=0;k<n;k++){
    float I=x[2*k], Q=x[2*k+1];
    y[k]=I*I+Q*Q;
}

Magnitude squared is sufficient when only relative power/comparison is required. Avoiding sqrt saves work.

Exercise 16.8

Optimize a 2D convolution for cache locality. What dimensions would you consider and why?

Consider contiguous memory order, which dimension is innermost, reuse of input tiles, coefficient reuse, output tile size, padding/boundaries, and vectorization direction. A tiled/blocking strategy can improve reuse by keeping working sets in cache/local memory. The best layout depends on row-major/column-major storage and target hardware.
