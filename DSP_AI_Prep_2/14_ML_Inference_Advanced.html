ML inference: understand the graph as a systems workload

The role calls out machine learning and neural-network graphs as an advantage. fileciteturn0file0L30-L31 At interview level, do not stop at “a neural network is matrix multiplications.” Inference is a graph of operators, tensors, memory transfers, shapes, layouts, and numerical formats.

Exercise 14.1

A tensor is shaped [1, 128, 64]. What could each dimension mean? Why must you know semantics before optimizing layout?

It could represent batch, sequence, channels/features, or another domain-specific arrangement. Layout determines which dimension is contiguous and therefore affects memory access and vectorization. Optimizing a layout without understanding operator expectations can create costly transposes or incorrect results.

Exercise 14.2

Why can quantizing weights alone help memory but fail to provide the expected speedup?

If activations remain high precision, computation may still occur in a costly format; conversions can add overhead; the target hardware may not accelerate the chosen integer type; memory may not be the bottleneck; or kernels may not be optimized for the quantized format.

Exercise 14.3

Explain operator fusion using a simple example: Conv → BiasAdd → ReLU.

Without fusion, Conv writes an intermediate tensor, BiasAdd reads/writes it, and ReLU reads/writes again. A fused kernel can compute convolution, add bias, and apply ReLU while the intermediate value remains in registers/local cache, reducing memory traffic and synchronization.

Exercise 14.4

A fused kernel is faster but consumes more registers and causes register spills. Explain how it can become slower at larger tensor sizes.

Fusion increases live values. Excessive register pressure can force spills to memory, increasing loads/stores and reducing occupancy or instruction efficiency. A fusion that helps one shape or architecture can hurt another. Profile across representative shapes.

Exercise 14.5

What is the difference between model-level accuracy and numerical kernel correctness?

Kernel correctness asks whether an operator produces outputs within an accepted numerical specification relative to a reference. Model-level accuracy measures end-task performance (classification accuracy, detection metric, etc.). A small kernel error might have no practical model impact—or could compound into a significant accuracy loss.

Exercise 14.6

Design a test plan for an int8 inference kernel.
  1. Compare against a high-precision reference.
  2. Test representative and extreme tensor ranges.
  3. Test zero-point/scale boundaries if applicable.
  4. Test odd sizes and vector tails.
  5. Check saturation and overflow.
  6. Measure latency/throughput.
  7. Test multiple tensor shapes/layouts.
  8. Run end-to-end model accuracy regression.
