13 — Hard DSP Problems

Advanced filtering, FFT, multirate, numerical behavior and implementation

Hard DSP problem set

These are deliberately less “textbook.” For each one, write equations first, then an implementation plan, then identify numerical/performance risks.

Exercise 13.1

You have x[n] sampled at 48 kHz and need to decimate by 3. Explain the correct processing order and why naïvely dropping 2 out of every 3 samples can alias.

Before downsampling by M=3, frequencies above the new Nyquist limit must be sufficiently attenuated. Therefore apply an appropriate low-pass anti-alias filter, then retain every third sample. Simply discarding samples leaves high-frequency content that folds into lower frequencies after decimation.

Exercise 13.2

A 1024-point FFT runs in 80 µs. A direct DFT would scale roughly quadratically. Explain why increasing N by 2 does not make FFT time exactly 4×.

The FFT scales approximately O(N log N), not O(N²). Doubling N roughly changes work by 2·log₂(2N)/log₂(N), which is much less than 4×. Real runtime also depends on implementation constants, memory behavior, vectorization, and architecture.

Exercise 13.3

A signal contains tones at 1 kHz and 1.05 kHz. You sample at 8 kHz. How would you choose an FFT length to distinguish them, and what practical caveats exist?

Frequency-bin spacing is Fs/N. To get 50 Hz spacing, N=800 gives that nominal spacing. But “distinguish” also depends on window main-lobe width, SNR, leakage, tone coherence, and estimator choice. Zero-padding interpolates the sampled spectrum but does not create new underlying resolution.

Exercise 13.4

Explain why an FIR can be implemented using overlap-save/overlap-add for long convolution, and what performance advantage this can provide.

Long time-domain convolution costs O(NM) for block size N and filter length M. FFT-based block convolution can reduce asymptotic work by transforming convolution into multiplication in the frequency domain. Overlap-save/overlap-add handle block boundaries correctly. The trade-off includes FFT cost, latency, memory, and block-size effects.

Exercise 13.5

A DC offset enters an IIR filter with feedback. Why can a small fixed-point bias become much more visible than in a single FIR multiply?

Feedback can repeatedly reprocess the quantization/rounding error. The state can accumulate or amplify bias depending on pole locations and structure. IIR fixed-point design therefore needs careful scaling, state bounds, coefficient quantization, and stability analysis.

Exercise 13.6

A filter output has occasional spikes at exactly the maximum positive int16 value. What does that suggest, and how would you distinguish legitimate saturation from a bug?

It may indicate saturation/clipping. Check input ranges, gain, accumulator headroom, saturation counters, and whether spikes correlate with large signals. Compare against a high-precision reference and inspect intermediate stages to identify the first point of range violation.
