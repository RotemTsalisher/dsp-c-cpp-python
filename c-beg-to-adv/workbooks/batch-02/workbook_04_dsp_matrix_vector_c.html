DSP Matrix & Vector Operations — C

Batch 02 · Ground zero → senior DSP kernels · ANSI C11 · 15 exercises

Standalone deep-dive notebook (C): comprehensive path through efficient vector and matrix work for signal processing. Fixed buffers only; <stdio.h>, <math.h>, <string.h>. Solutions stay behind the reveal button.

How to use this notebook

This guide teaches efficient matrix and vector operations for DSP in ANSI C11, starting from absolute zero and ending at senior-level kernel style. There is no magic library here: every algorithm is something you own as loops over flat buffers.

Mental model

A vector is a 1-D block of samples or coefficients. A matrix is a 2-D block of coefficients, usually stored row-major as one contiguous array of length rows * cols. Almost every “fancy” DSP linear stage is built from: scale, add, dot, outer product, matrix–vector, and matrix–matrix.

Efficiency principles you will practice

  • Walk memory contiguously in the inner loop.
  • Prefer in-place updates (AXPY) when a third buffer is not required.
  • Match layout (row-major / planar / interleaved) to the hot access pattern.
  • Use blocking when matrices outgrow the cache.
  • Fuse passes that touch the same data.
  • Respect numerical edge cases (zero norms, long accumulations).

Exercise 1 — Vectors as sequences of samples
What you are learning: A vector is an ordered list of numbers. In DSP it usually means a block of time-domain samples or frequency-bin magnitudes. Index 0 is the oldest or lowest-frequency sample depending on convention — you must pick one and stay consistent.

Exercise 2 — Scalar gain and element-wise vector add
What you are learning: Scaling multiplies every sample by one constant (digital gain). Element-wise addition mixes two buffers of equal length. These are the cheapest linear operations in a signal chain.

DSP context: Channel A is attenuated by 0.5; then it is mixed with channel B for a mono monitor path.

Requirements:

  • Given vectors a[6] and b[6] with distinct values you choose.
  • Compute scaled[i] = 0.5 * a[i] for all i.
  • Compute mix[i] = scaled[i] + b[i] for all i.
  • Print scaled and mix as two separate lines of space-separated %.4f values.
  • Do not use matrices yet.
#include <stdio.h>

int main(void)
{

What you are learning: A matrix is a rectangular grid of numbers. In C/C++ a common layout is row-major: all columns of row 0 sit first in memory, then row 1, and so on. Indexing A[r][c] means row r, column c. In DSP, rows often mean filter taps or channel coefficients.

Exercise 4 — Inner product (dot product)
What you are learning: The dot product of two equal-length vectors is the sum of products of matching elements. It measures how aligned two signals are. Related DSP uses: correlation at lag 0, energy when one vector is used twice, projection onto a template.

DSP context: Compare a reference comb template against a captured frame of the same length.

Requirements:

  • Implement a function that takes two double pointers and a length, returns the double dot product.
  • Use vectors of length 5 with values you choose.
  • Print the result with %.6f.
  • Document in a one-line comment that length must match.
#include <stdio.h>

/* lengths of a and b must be equal to n */
double dot(double const *a, double const *b, int n)
{
    double s = 0.0;
    for (int i = 0; i < n; ++i) {
        s += a[i] * b[i];
    }
    return s;
}

int main(void)
{
    double ref[5] = {1.0, 0.5, 0.0, -0.5, -1.0};
    double frame[5] = {0.8, 0.4, 0.1, -0.4, -0.9};
    printf("%.6f\n", dot(ref, frame, 5));
    return 0;
}
Dot product is the backbone of almost every later matrix row operation — a matrix-vector product is many dots.

Exercise 5 — Euclidean norm and unit-length normalize
What you are learning: The Euclidean (L2) norm of vector x is sqrt(sum x_i^2). Dividing each element by the norm produces a unit vector (norm 1), useful for comparing shapes independent of gain. Guard the zero-vector case.

DSP context: Normalize a short PSD bin vector so peak shape can be compared across sessions with different overall power.

Requirements:

  • Implement norm2(x, n) returning the L2 norm.
  • Implement normalize(x, n) that scales x in place to unit length when norm > 0; if norm == 0 leave x unchanged and return 0, else return 1.
  • Demonstrate on a length-4 vector; print norm before, elements after, and success flag.
#include <math.h>
#include <stdio.h>

double norm2(double const *x, int n)
{
    double s = 0.0;
    for (int i = 0; i < n; ++i) {
        s += x[i] * x[i];
    }
    return sqrt(s);
}

int normalize(double *x, int n)
{
    double const nrm = norm2(x, n);
    if (nrm == 0.0) {
        return 0;
    }
    for (int i = 0; i < n; ++i) {
        x[i] /= nrm;
    }
    return 1;
}

int main(void)
{
    double x[4] = {3.0, 0.0, 4.0, 0.0};
    printf("norm_before=%.6f\n", norm2(x, 4));
    int ok = normalize(x, 4);
    for (int i = 0; i < 4; ++i) printf("%.6f ", x[i]);
    putchar('\n');
    printf("ok=%d\n", ok);
    return 0;
}
Always protect against division by zero. Norm of (3,0,4) is 5 — a classic check.

Exercise 6 — Matrix–vector product y = A x
What you are learning: If A is m×n and x has length n, then y has length m and y_i is the dot product of row i of A with x. This is how a bank of FIR filters, a linear mixing stage, or a projection onto basis rows is written.

DSP context: Three analysis filters (rows) process one shared input frame x of length 4.

Requirements:

  • A is 3×4, x length 4, y length 3.
  • Implement matvec that writes y.
  • Print y with %.4f per component.
  • Use nested loops; document that inner dimension must match.
#include <stdio.h>

/* A: m x n, x: n, y: m */
void matvec(double const *A, int m, int n, double const *x, double *y)
{
    for (int i = 0; i < m; ++i) {
        double s = 0.0;
        for (int j = 0; j < n; ++j) {
            s += A[i * n + j] * x[j];
        }
        y[i] = s;
    }
}

int main(void)
{
    double A[3 * 4] = {
        1, 0, 0, 0,
        0.5, 0.5, 0, 0,
        0.25, 0.25, 0.25, 0.25
    };
    double x[4] = {1.0, 2.0, 3.0, 4.0};
    double y[3];
    matvec(A, 3, 4, x, y);
    for (int i = 0; i < 3; ++i) printf("%.4f ", y[i]);
    putchar('\n');
    return 0;
}
Flattened row-major storage A[i*n+j] matches how most DSP buffers are packed.

Exercise 7 — Matrix–matrix product C = A B
What you are learning: If A is m×k and B is k×n, then C is m×n with C_ij = sum over p of A_ip * B_pj. Cost is O(m*n*k). Dimension mismatch on the shared k is a hard error — check it.

DSP context: Cascade two small mixing stages: first maps 3 inputs to 2 mid channels, second maps 2 mid to 2 outputs.

Requirements:

  • A is 2×3, B is 3×2 — wait: for cascade A (2×3) then B (3×2) gives C (2×2). Use A 2×3, B 3×2.
  • Implement matmul writing C as a flat row-major array.
  • Print C as a 2×2 grid with %.2f.
#include <stdio.h>

void matmul(double const *A, int m, int k,
            double const *B, int n,
            double *C)
{
    for (int i = 0; i < m; ++i) {
        for (int j = 0; j < n; ++j) {
            double s = 0.0;
            for (int p = 0; p < k; ++p) {
                s += A[i * k + p] * B[p * n + j];
            }
            C[i * n + j] = s;
        }
    }
}

int main(void)
{
    double A[2 * 3] = {1, 2, 3, 4, 5, 6};
    double B[3 * 2] = {7, 8, 9, 10, 11, 12};
    double C[2 * 2];
    matmul(A, 2, 3, B, 2, C);
    for (int i = 0; i < 2; ++i) {
        for (int j = 0; j < 2; ++j) printf("%6.2f", C[i * 2 + j]);
        putchar('\n');
    }
    return 0;
}
Classic ijk triple loop. Result for this textbook data is [[58,64],[139,154]].

Exercise 8 — Transpose A^T
What you are learning: Transpose swaps rows and columns: (A^T)_ij = A_ji. If A is m×n, A^T is n×m. In DSP you transpose when converting between channel-major and time-major packing, or when turning a tall analysis matrix into a wide synthesis layout.

DSP context: A 2×4 measurement matrix must be written as 4×2 for a downstream API that expects the opposite orientation.

Requirements:

  • Implement transpose of flat row-major A (m×n) into T (n×m).
  • Demonstrate with m=2, n=4.
  • Print both matrices.
  • Do not mutate A unless you implement a separate in-place path (not required here).
#include <stdio.h>

void transpose(double const *A, int m, int n, double *T)
{
    for (int i = 0; i < m; ++i) {
        for (int j = 0; j < n; ++j) {
            T[j * m + i] = A[i * n + j];
        }
    }
}

static void print_mat(double const *M, int rows, int cols)
{
    for (int r = 0; r < rows; ++r) {
        for (int c = 0; c < cols; ++c) printf("%6.2f", M[r * cols + c]);
        putchar('\n');
    }
}

int main(void)
{
    double A[2 * 4] = {1, 2, 3, 4, 5, 6, 7, 8};
    double T[4 * 2];
    transpose(A, 2, 4, T);
    printf("A:\n"); print_mat(A, 2, 4);
    printf("T:\n"); print_mat(T, 4, 2);
    return 0;
}
Out-of-place transpose is safest. In-place for non-square needs careful packing and is a later senior topic.

Exercise 9 — Outer product u v^T
What you are learning: The outer product of column vector u (length m) and row vector v^T (v length n) is an m×n matrix with M_ij = u_i * v_j. It builds rank-1 updates used in adaptive filters, covariance sketches, and low-rank models.

DSP context: Update a 3×4 weight matrix contribution from a residual vector u and a feature vector v.

Requirements:

  • Implement outer(u, m, v, n, M) writing M as m×n row-major.
  • Print the matrix.
  • Verify that every entry equals u_i * v_j for your chosen vectors.
#include <stdio.h>

void outer(double const *u, int m, double const *v, int n, double *M)
{
    for (int i = 0; i < m; ++i) {
        for (int j = 0; j < n; ++j) {
            M[i * n + j] = u[i] * v[j];
        }
    }
}

int main(void)
{
    double u[3] = {1.0, 2.0, 3.0};
    double v[4] = {0.5, 1.0, 1.5, 2.0};
    double M[3 * 4];
    outer(u, 3, v, 4, M);
    for (int i = 0; i < 3; ++i) {
        for (int j = 0; j < 4; ++j) printf("%6.2f", M[i * 4 + j]);
        putchar('\n');
    }
    return 0;
}
Outer product fills a matrix without needing a third loop — every cell is independent.

Exercise 10 — AXPY: y ← α x + y (BLAS Level-1 pattern)
What you are learning: AXPY (a·x plus y) updates y in place: y_i += alpha * x_i. It is a BLAS Level-1 building block. DSP uses it for residual updates, gradient steps, and mixing a scaled reference into a buffer without allocating a third array.

DSP context: Apply a learning-rate scaled correction vector into a coefficient buffer already holding the current estimate.

Requirements:

  • Implement axpy(alpha, x, y, n) modifying y in place.
  • Demonstrate with n=6, alpha=0.1.
  • Print y before and after on two lines.
  • x must remain unchanged.
#include <stdio.h>

void axpy(double alpha, double const *x, double *y, int n)
{
    for (int i = 0; i < n; ++i) {
        y[i] += alpha * x[i];
    }
}

static void print_v(double const *v, int n)
{
    for (int i = 0; i < n; ++i) printf("%.4f ", v[i]);
    putchar('\n');
}

int main(void)
{
    double x[6] = {1, 1, 1, 1, 1, 1};
    double y[6] = {0.5, 0.4, 0.3, 0.2, 0.1, 0.0};
    print_v(y, 6);
    axpy(0.1, x, y, 6);
    print_v(y, 6);
    return 0;
}
In-place update saves memory bandwidth — critical on embedded DSP with tight RAM.

Exercise 11 — Efficient GEMV with contiguous row access
What you are learning: GEMV is general matrix–vector multiply. Efficiency comes from streaming contiguous memory: for row-major A, keep the outer loop on rows and walk columns of that row sequentially. Accumulate into a register (local double) before writing y[i]. Avoid jumping around columns of different rows in the inner loop.

DSP context: A tall 8×4 analysis matrix must run every hop on a Cortex-class core; layout and loop order matter for cache lines.

Requirements:

  • Implement gemv_rowmajor(A, m, n, x, y) with m=8, n=4.
  • Zero y first, then accumulate.
  • Print y.
  • In comments, state why the inner loop walks A[i*n + j] consecutively.
#include <stdio.h>

void gemv_rowmajor(double const *A, int m, int n,
                   double const *x, double *y)
{
    for (int i = 0; i < m; ++i) {
        /* Inner walk is contiguous in row-major storage. */
        double acc = 0.0;
        double const *row = A + i * n;
        for (int j = 0; j < n; ++j) {
            acc += row[j] * x[j];
        }
        y[i] = acc;
    }
}

int main(void)
{
    double A[8 * 4];
    for (int i = 0; i < 8 * 4; ++i) A[i] = (double)((i % 5) + 1) * 0.1;
    double x[4] = {1, 0, 1, 0};
    double y[8];
    gemv_rowmajor(A, 8, 4, x, y);
    for (int i = 0; i < 8; ++i) printf("%.4f ", y[i]);
    putchar('\n');
    return 0;
}
Pointer to the start of each row makes the contiguous walk obvious and helps the compiler.

Exercise 12 — Blocked (tiled) matrix multiply for locality
What you are learning: Naive matmul streams B poorly. Blocking partitions the multiplication into tiles of size BS×BS so a tile of A, B, and C stays hot in cache. Choose a small BS (e.g. 2) for this exercise so the idea is visible without huge matrices.

DSP context: Multiply two 4×4 matrices on a device with a tiny data cache; demonstrate a 2×2 tiling scheme.

Requirements:

  • Implement matmul_blocked(A, B, C, N, BS) for square N×N with tile size BS.
  • Use N=4, BS=2.
  • Initialize A and B with simple patterns; print C.
  • Compare mentally to naive ijk — output must match a correct multiply.
#include <stdio.h>
#include <string.h>

void matmul_blocked(double const *A, double const *B, double *C,
                    int N, int BS)
{
    memset(C, 0, (size_t)(N * N) * sizeof(double));
    for (int ii = 0; ii < N; ii += BS) {
        for (int jj = 0; jj < N; jj += BS) {
            for (int kk = 0; kk < N; kk += BS) {
                int i_max = ii + BS < N ? ii + BS : N;
                int j_max = jj + BS < N ? jj + BS : N;
                int k_max = kk + BS < N ? kk + BS : N;
                for (int i = ii; i < i_max; ++i) {
                    for (int j = jj; j < j_max; ++j) {
                        double s = C[i * N + j];
                        for (int k = kk; k < k_max; ++k) {
                            s += A[i * N + k] * B[k * N + j];
                        }
                        C[i * N + j] = s;
                    }
                }
            }
        }
    }
}

int main(void)
{
    int const N = 4;
    double A[16], B[16], C[16];
    for (int i = 0; i < N; ++i)
        for (int j = 0; j < N; ++j) {
            A[i * N + j] = (i == j) ? 1.0 : 0.0;
            B[i * N + j] = (double)(i + j);
        }
    matmul_blocked(A, B, C, N, 2);
    for (int i = 0; i < N; ++i) {
        for (int j = 0; j < N; ++j) printf("%5.1f", C[i * N + j]);
        putchar('\n');
    }
    return 0;
}
With A = I, C equals B — a fast correctness check for blocked multiply.

Exercise 13 — FIR filtering as a structured matrix–vector product
What you are learning: A length-L FIR filter applied to a signal can be written as multiplying a Toeplitz (banded) matrix by a vector of samples. Direct convolution y[n] = sum_k h[k]*x[n-k] is usually faster in code, but understanding the matrix form connects filter banks to linear algebra.

DSP context: Apply a 3-tap FIR h = {0.25, 0.50, 0.25} to an input of length 8, producing an output of length 8 with zero past samples (same as causal convolution with zeros before start).

Requirements:

  • Implement fir_direct(h, L, x, N, y) with zero initial state.
  • Also implement fir_via_matvec that builds an N×N Toeplitz-style matrix (or N×N banded) and calls your matvec — or builds only the needed products without a full dense matrix if you document the equivalence.
  • Print both outputs; they must match within floating tolerance (print both).
#include <stdio.h>
#include <string.h>

void fir_direct(double const *h, int L, double const *x, int N, double *y)
{
    for (int n = 0; n < N; ++n) {
        double s = 0.0;
        for (int k = 0; k < L; ++k) {
            int t = n - k;
            if (t >= 0) s += h[k] * x[t];
        }
        y[n] = s;
    }
}

void fir_via_matvec(double const *h, int L, double const *x, int N, double *y)
{
    double A[8 * 8];
    memset(A, 0, sizeof A);
    for (int n = 0; n < N; ++n) {
        for (int k = 0; k < L; ++k) {
            int t = n - k;
            if (t >= 0) A[n * N + t] = h[k];
        }
    }
    for (int n = 0; n < N; ++n) {
        double s = 0.0;
        for (int t = 0; t < N; ++t) s += A[n * N + t] * x[t];
        y[n] = s;
    }
}

int main(void)
{
    double h[3] = {0.25, 0.50, 0.25};
    double x[8] = {1, 2, 3, 4, 5, 6, 7, 8};
    double y1[8], y2[8];
    fir_direct(h, 3, x, 8, y1);
    fir_via_matvec(h, 3, x, 8, y2);
    for (int i = 0; i < 8; ++i) printf("%.4f ", y1[i]); putchar('\n');
    for (int i = 0; i < 8; ++i) printf("%.4f ", y2[i]); putchar('\n');
    return 0;
}
Same math, two views: streaming FIR vs explicit linear operator. Production code usually keeps the direct form.

Exercise 14 — Row-major vs column-major and strided channel access
What you are learning: Layout decides performance. Row-major packs rows contiguously. Column-major packs columns contiguously (common in Fortran/BLAS). Interleaved stereo [L0 R0 L1 R1…] is a stride-2 view of two channel vectors. Senior DSP work means picking a layout and writing kernels that walk memory sequentially whenever possible.

DSP context: A stereo DMA buffer is interleaved. You must compute per-channel energy and a mono mix without first de-interleaving into two full buffers (optional scratch of size 1 is fine).

Requirements:

  • Buffer layout: double interleaved[2*N] with N=6: L0,R0,L1,R1,…
  • Compute energy_L = sum L^2, energy_R = sum R^2 using stride-2 pointer walks.
  • Write mono[i] = 0.5*(L[i]+R[i]) into a separate mono[N] array.
  • Print energies and mono.
  • In comments, contrast this with a planar layout L[N], R[N].
#include <stdio.h>

int main(void)
{
    int const N = 6;
    double interleaved[12] = {
        0.5, -0.5, 0.4, -0.4, 0.3, -0.3,
        0.2, -0.2, 0.1, -0.1, 0.0,  0.0
    };
    /* Planar would be L[N], R[N] contiguous — better for long single-channel FIR. */
    double energy_L = 0.0, energy_R = 0.0;
    double mono[6];
    for (int i = 0; i < N; ++i) {
        double const L = interleaved[2 * i];
        double const R = interleaved[2 * i + 1];
        energy_L += L * L;
        energy_R += R * R;
        mono[i] = 0.5 * (L + R);
    }
    printf("energy_L=%.6f energy_R=%.6f\n", energy_L, energy_R);
    for (int i = 0; i < N; ++i) printf("%.4f ", mono[i]);
    putchar('\n');
    return 0;
}
Stride-aware kernels avoid unnecessary copies. Choose planar vs interleaved based on which axis you process most often.

Exercise 15 — Fused residual kernel and compensated energy (production style)
What you are learning: Senior DSP kernels fuse steps that would otherwise thrash memory: compute prediction, residual, and energy in one pass when possible. Long sums of squares can lose precision; a compensated (Kahan) sum is one classical remedy without external libraries. Structure APIs so buffers have clear ownership and no hidden temporaries of size N².

DSP context: Given a reference template t and observation x (length 8), compute scalar gain g = (t·x)/(t·t), residual r = x - g*t, and residual energy ||r||² with a compensated accumulator. Print g, energy, and the residual vector.

Requirements:

  • Single function process_residual(t, x, n, r, &g, &energy) writing residual into r.
  • Use Kahan (or equivalent compensated) summation for the energy of r.
  • Handle t·t == 0 by setting g=0 and r=x.
  • No STL, no BLAS library — only your own loops.
  • Print g, energy, then residual values.
#include <stdio.h>

void process_residual(double const *t, double const *x, int n,
                      double *r, double *g_out, double *energy_out)
{
    double tt = 0.0, tx = 0.0;
    for (int i = 0; i < n; ++i) {
        tt += t[i] * t[i];
        tx += t[i] * x[i];
    }
    double g = (tt == 0.0) ? 0.0 : (tx / tt);
    double energy = 0.0;
    double c = 0.0; /* Kahan compensation */
    for (int i = 0; i < n; ++i) {
        r[i] = x[i] - g * t[i];
        double const y = r[i] * r[i] - c;
        double const sum = energy + y;
        c = (sum - energy) - y;
        energy = sum;
    }
    *g_out = g;
    *energy_out = energy;
}

int main(void)
{
    double t[8] = {1,1,1,1,0,0,0,0};
    double x[8] = {2,2,2,2,1,1,1,1};
    double r[8];
    double g, energy;
    process_residual(t, x, 8, r, &g, &energy);
    printf("g=%.6f energy=%.6f\n", g, energy);
    for (int i = 0; i < 8; ++i) printf("%.4f ", r[i]);
    putchar('\n');
    return 0;
}
