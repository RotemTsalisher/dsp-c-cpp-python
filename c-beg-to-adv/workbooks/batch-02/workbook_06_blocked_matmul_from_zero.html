Blocked Matrix Multiplication — From Zero

Companion to Exercise 12 in workbook_04_dsp_matrix_vector_c.html · Batch 02

What this workbook is: the exact theory-and-practice explanation for blocked (tiled) matrix multiplication, written for a complete beginner. It matches Exercise 12 in the DSP matrix/vector C notebook: multiply two 4×4 matrices using tiles of size 2×2. Handwriting drills are at the end; answers sit behind Reveal solution.

1. What is a matrix (tiny reminder)

A matrix is a grid of numbers.

Example 2×2:

A = | 1 2 | | 3 4 |
  • Row = horizontal line
  • Column = vertical line
  • Aij = entry in row i, column j (we count from 0 in C, from 1 in math books — same idea)

2. What does “matrix multiply” mean?

If C = A × B, each entry of C is a dot product:

C_ij = sum over k of ( A_ik * B_kj )

In words:

To get the number in row i, column j of C:
take row i of A, take column j of B, multiply matching pairs, add them up.

Tiny example (do this once by hand)

A = | 1 2 | B = | 5 6 | | 3 4 | | 7 8 |
C_00 = 1*5 + 2*7 = 5 + 14 = 19 C_01 = 1*6 + 2*8 = 6 + 16 = 22 C_10 = 3*5 + 4*7 = 15 + 28 = 43 C_11 = 3*6 + 4*8 = 18 + 32 = 50

So

C = | 19 22 | | 43 50 |

That is all matrix multiply is. Blocking does not change this math. It only changes the order of the work.

3. The “naive” way (what you already know)

In code people usually write three loops:

for i = 0 .. N-1          // which row of C
  for j = 0 .. N-1        // which column of C
    for k = 0 .. N-1      // sum along the shared dimension
      C[i][j] += A[i][k] * B[k][j]

For each Cij you walk along a row of A and a column of B.

On paper this is fine. On a real CPU it can be slow for large N, because of cache.

4. Why computers care about order (the real reason for blocking)

Simple picture of memory

  • Numbers live in RAM (big, slow).
  • The CPU has a tiny cache (small, fast).

When the CPU needs a number:

  1. If it’s already in cache → fast (cache hit).
  2. If not → fetch from RAM → slow (cache miss), and usually a whole chunk comes in, not one number.

What goes wrong in naive matmul

While computing one row of C, you keep reading columns of B.

In row-major storage (C arrays), a row sits together in memory, but a column is scattered:

Row 0:  B00 B01 B02 B03     ← consecutive in memory
Row 1:  B10 B11 B12 B13
...
Column 0 is: B00, B10, B20, B30  ← far apart

So the naive inner loop often jumps around in B. For big matrices, you keep kicking useful data out of the tiny cache and reloading it. Same math, worse performance.

Blocking / tiling = do the multiply in small squares so the pieces of A, B, and C you need fit in cache and get reused before you move on.

5. The big idea of blocking (tiles)

Imagine a 4×4 matrix cut into 2×2 tiles (this is exactly Exercise 12: N=4, BS=2):

A =  [ A00 | A01 ]      B =  [ B00 | B01 ]
     [ ----+---- ]           [ ----+---- ]
     [ A10 | A11 ]           [ B10 | B11 ]

C =  [ C00 | C01 ]
     [ ----+---- ]
     [ C10 | C11 ]

Each A00, B00, C00, … is a 2×2 block, not a single number.

Important formula (block version of the same multiply)

For the top-left block of C:

C00 = A00 * B00 + A01 * B10

Same pattern as numbers, but each “multiplication” is a small matrix multiply, and “+” adds matrices entrywise.

So:

  1. Multiply two small 2×2 pieces.
  2. Add into the matching 2×2 piece of C.
  3. Move to the next tile pair.

You still get the same final C as the naive method. You only changed when each Aik Bkj product is done.

6. Walkthrough with the notebook’s test case

In the solution, A is the identity (1s on the diagonal, 0 elsewhere), and Bij = i + j.

For N=4:

A = I = | 1 0 0 0 | B = | 0 1 2 3 | | 0 1 0 0 | | 1 2 3 4 | | 0 0 1 0 | | 2 3 4 5 | | 0 0 0 1 | | 3 4 5 6 |

Fact: I × B = B. So if your blocked multiply is correct, C must equal B. That is the exercise’s built-in check.

How tiles cover this

Tiles of size 2:

BlockRowsCols
000–10–1
010–12–3
102–30–1
112–32–3

For top-left C00 (rows 0–1, cols 0–1):

C00 += A00 * B00 C00 += A01 * B10

Because A = I:

  • A00 = I2 (2×2 identity)
  • A01 = 0

So only the first term matters: C00 = B00. Same for other blocks → whole C = B.

7. What the six loops mean (mapping to the code)

Exercise code has outer block loops and inner element loops:

for ii = 0, 2, ...     // start row of C-tile
  for jj = 0, 2, ...   // start col of C-tile
    for kk = 0, 2, ... // which "k-tile" contributes to this C-tile
      // now multiply the small pieces:
      for i = ii .. ii+BS-1
        for j = jj .. jj+BS-1
          for k = kk .. kk+BS-1
            C[i][j] += A[i][k] * B[k][j]
LoopMeaning
ii, jjWhich output tile of C you are filling
kkWhich pair of tiles from A and B you add into that output tile
i, j, kOrdinary multiply inside those small tiles

i_max, j_max, k_max only handle the case when N is not divisible by BS (last partial tile). For N=4, BS=2 they never cut short.

Start with zeros: C must begin at 0 because each Cij is built by adding several block contributions (kk loop).

8. One full numeric micro-example

If N=2, BS=2, there is one tile. Blocking = normal multiply. Not interesting.

Better: think of N=4 but compute one entry two ways.

Entry C0,0 naive

C_00 = A_00*B_00 + A_01*B_10 + A_02*B_20 + A_03*B_30

With A = I: only A00 = 1, so C00 = B00 = 0.

Same entry blocked (BS=2)

  • From kk=0: sum k=0,1 → A00B00 + A01B10 = 1·0 + 0·1 = 0
  • From kk=2: sum k=2,3 → A02B20 + A03B30 = 0

Total still 0. Same answer, different grouping.

That is the whole theory: associativity of addition — you can add the products in tile-sized chunks.

9. Why DSP people care

On headphones / AFE / MCU:

  • Matrices for mixing, beamforming, filter banks can be dozens–hundreds on a side.
  • Cache is tiny.
  • Blocked multiply (and related ideas: GEMM, tiling) is how libraries get speed without changing the math.

Exercise 12 is the idea in miniature (4×4 with 2×2 tiles), not a production BLAS.
