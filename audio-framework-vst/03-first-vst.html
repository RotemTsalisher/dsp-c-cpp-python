Part 1 · Phases 5–9 Baby-step mode

First VST — the simplest gain plugin

Goal: understand integration, not fancy DSP. Mathematically: y[n] = x[n] × gain. Architecturally: a new (or studied) C module + VST3 header + VS project.

Interactive rule Do one step, implement it yourself, build if asked, then stop. Use an AI/human mentor for review between steps. Do not binge-paste the whole module.

Phase 5 — Where does the VST belong?

Reasoning checklist (answer before reading further):

  1. What architecture did we find? → Thin JUCE wrapper around C AudioModuleCore.
  2. Where does audio enter the plugin? → Host → GenericProcessor::processBlock.
  3. Where does DSP happen? → Core->Calc in your module .c.
  4. Where does output leave? → Copy from Outputs back to JUCE buffer → host.
  5. What should the plugin integrate with? → Provide amCore + ioConfigs; reuse GenericProcessor.
  6. Dependencies? → Framework C sources, JUCE modules listed in the .vcxproj.

Conclusion: New plugin lives under Modules/<YourName>/ with DSP in .c/.h and glue in VST3/<YourName>Plugin.h (+ VS project). You almost never fork GenericProcessor for a normal module.

Phase 6 — Scope of the first plugin

Input Audio → Gain → Output Audio y[n] = x[n] × gain

In scope: Init / Calc / Free / SetValue / GetValue / GetParamInfo, Plugin.h, build, load in host.

Out of scope for VST #1: custom GUI, MIDI, presets, fancy DSP, full product checklist.

Two learning tracks (pick with your mentor):

  • Study track: read and rebuild existing Modules/Gain (fastest map of reality).
  • Create track: copy Modules/Template → e.g. Modules/SimpleGain and fill it in baby steps (best for muscle memory).

Below assumes the create track. If you use Gain as reference, open those files beside each step.

Step 2

Declare the AudioModuleCore

What / Why

Register the module’s function pointers so GenericProcessor can call them.

Code (minimum — fill in your header)

static const AudioModuleCore SimpleGain =
{
   "SimpleGain",
   SimpleGainInit,
   SimpleGainCalc,
   0,                 /* no Idle */
   SimpleGainFree,
   SimpleGainSetValue,
   SimpleGainGetValue,
   BypassSetData,     /* or your SetData */
   BypassGetData,
   SimpleGainGetParamInfo,
   0                  /* DefaultFormat */
};
What?
Static “class object” for this module type.
How?
Each field is a function pointer (or 0 / bypass helper).
Why?
Polymorphism without C++ vtables in the DSP layer.
STOP AND WAIT Show your header. Next: private state struct.
Step 3

Private state + Init

typedef struct {
   float Gain;   /* linear gain, not dB */
} SimpleGainSetup;

void SimpleGainInit(AudioModule* setup)
{
   SimpleGainSetup* s = (SimpleGainSetup*)afwAlloc(sizeof(SimpleGainSetup));
   setup->Specific = s;
   s->Gain = 0.1f;   /* ~ -20 dB starting point, like Template */
}

C concepts: heap allocation via framework allocator; ownership stored in Specific; Init may run more than once across prepare — follow patterns in existing modules when you hit re-init.

STOP AND WAIT Implement Init + matching Free skeleton only.
Step 4

Free

void SimpleGainFree(AudioModule* setup)
{
   SimpleGainSetup* s = (SimpleGainSetup*)setup->Specific;
   afwFree(s);
}

Why: every afwAlloc in Init needs a matching free — RAII equivalent in C.

STOP AND WAIT
Step 5

Calc — the audio math

Now implement processing yourself. Constraints:

  • Loop channels 0 .. NumInputs-1
  • Loop samples 0 .. BlockLength-1
  • Outputs[ch][i] = Inputs[ch][i] * Gain
  • No allocations, no file I/O
Hint 1 — Conceptual

Planar buffers: each channel is its own contiguous float array.

Hint 2 — Architectural

Look at TemplateCalc or GainCalc (Gain uses dspVectorScale).

Hint 3 — Implementation 
for (int ch = 0; ch < setup->NumInputs; ++ch)
  for (int i = 0; i < setup->BlockLength; ++i)
    setup->Outputs[ch][i] = setup->Inputs[ch][i] * s->Gain;
Hint 4 — Near solution

Cast Specific, then the nested loops above. Match Template’s structure.

Hint 5 — Full (only if you ask your mentor)

Mentor may paste TemplateCalc renamed — only after you request it.

STOP AND WAIT Paste your Calc for review before parameters.
Step 6

Parameters — dB mapping

UI thinks in dB; DSP needs linear gain.

dB value → SetValue → linear = 10^(dB/20) GetValue ← 20*log10(linear)

Reference (Gain module):

/* SetValue sketch */
s->Gain = value > GAIN_MIN ? powf(10.f, value * 0.05f) : 0.f;
/* GetValue sketch */
*value = s->Gain > 1e-5f ? 20.f * log10f(s->Gain) : GAIN_MIN;

Add range checks (RETURN_IF_VALUE_OUT_OF_RANGE macros from framework) like Gain does.

Step 10

Build

In Visual Studio: Configuration Debug, Platform x64, Build Solution.

Command explanation (if using MSBuild)

msbuild SimpleGainPlugin.sln /p:Configuration=Debug /p:Platform=x64
msbuild = VS build engine; /p: sets properties; output is a .vst3 dynamic library.

Checkpoint

Zero errors. Note the output path from the build log.

STOP AND WAIT Paste build success/errors.

Phase 8 — Trace one audio block

DAW thread → JUCE VST3 client → GenericProcessor::processBlock → copy → AudioModule.Inputs[ch][i] → SimpleGainCalc (your file) → AudioModule.Outputs[ch][i] → copy → JUCE AudioBuffer → DAW

At each arrow name: file · class/function · buffer · thread. Write this table yourself as an exercise; compare to GenericProcessor.cpp.

Phase 9 — Install / load

  • Binary type: VST3 plugin (DLL named .vst3 on Windows in this project style).
  • Typical install dir: C:\Program Files\Common Files\VST3 (many AFW post-build steps copy here — may need admin).
  • Discovery: Host scans VST3 folders; rescanning required after copy.
  • Good hosts for learning: JUCE AudioPluginHost under Dependencies, Reaper, pluginval.
Stale binary trap Host may keep an old copy loaded. Close host, rebuild, recopy, rescan.
End of Phase 9 — STOP When the plugin loads and audio passes with audible gain change, continue to testing, debugging, and the knowledge check.
