From beginner to expert VST developer in this repository

This course teaches you how AudioFramework (AFW) turns C audio modules into VST3 plugins via a thin JUCE wrapper. You implement the code yourself in baby steps. The instructor (or AI mentor) sits beside you — they do not dump finished plugins.

Progress tracked in this browser

How this course works

Explain → tiny step → you implement → build/run → report back → review → next step. Do not paste 100–200 lines at once. Every implementation step ends with STOP AND WAIT before the next one.

What you will be able to do

Repository ↓ Audio Framework (C graph + modules) ↓ Audio pipeline (Inputs → Calc → Outputs) ↓ VST3 architecture (GenericProcessor + amCore) ↓ Plugin lifecycle (scan → load → prepare → process → free) ↓ Parameters (ParamInfo → GenericEditor) ↓ DSP (your Calc function) ↓ Build (Visual Studio · .vst3) ↓ Install / test / debug

Repository snapshot (why this is not a generic JUCE tutorial)

  • DSP is C, not C++ AudioProcessor subclasses per plugin.
  • Every VST3 reuses Framework/GenericProcessor + Framework/GenericEditor.
  • Per-plugin glue is a small header: Modules/<Name>/VST3/<Name>Plugin.h with amCore + ioConfigs.
  • Build system is Visual Studio (.sln / .vcxproj), not top-level CMake for modules.
  • Canonical starter: copy Modules/Template/. Simplest reference DSP: Modules/Gain/.

Mentor workflow (for AI or human instructor)

  1. Assume the learner knows programming + DSP, but not this repo or AFW VST wiring.
  2. Repository is the source of truth — if generic VST advice conflicts with AFW, follow AFW and explain the difference.
  3. Use progressive hints (conceptual → architectural → implementation → near solution → full only on request).
  4. Explain significant code at three levels: What / How / Why.
  5. Build after every tiny change.
Repo location

Study and build against your local AudioFramework clone (e.g. c:\repo\AudioFramework). This course folder is documentation only — it does not modify the framework.
