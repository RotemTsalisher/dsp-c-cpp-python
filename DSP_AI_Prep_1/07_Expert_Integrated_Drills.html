Exercise 7.1

You have a 128-tap FIR. Scalar implementation: 2.0 ms. SIMD implementation: 0.9 ms. But memory traffic doubles and power rises 18%. The deadline is 1.5 ms. Is SIMD a success?

For the stated deadline, yes on latency, but not automatically as a product decision. Investigate whether power increase violates constraints and whether memory traffic affects other workloads. Compare energy per processed block and system-level impact.

Exercise 7.2

A fixed-point implementation is 3× faster than floating point but clips on rare high-amplitude inputs. How do you debug it?

Instrument ranges, find the first stage where overflow occurs, calculate worst-case bounds, add headroom/guard bits or adjust scaling, define rounding/saturation policy, retest extreme and randomized inputs.

Exercise 7.3

A vectorized reduction is faster but produces slightly different results from scalar code. Is that a bug?

Not necessarily. Floating-point reassociation can change rounding. It is a bug if the numerical error exceeds the specified tolerance or changes downstream behavior beyond requirements. Establish a numerical specification.

Exercise 7.4

A neural network has many small operators. Each operator is individually fast, but total inference is slow.

Profile graph-level overhead, intermediate tensor traffic, allocations, synchronization and layout conversions. Consider fusion, buffer reuse, batching where latency permits, and reducing unnecessary copies.

Exercise 7.5

Design a real-time DSP pipeline with a 2 ms block deadline. What would you measure?

End-to-end latency, per-stage execution time, worst-case/jitter, CPU/DSP utilization, memory bandwidth/cache behavior, deadline misses, queue depth, and power if relevant.

Exercise 7.6

You are asked to optimize assembly before anyone has profiled the code. What do you say?

Agree that low-level optimization may be necessary, but first establish evidence. Profile and identify the hot/constrained kernel, then inspect generated assembly and optimize the relevant path.

Exercise 7.7

Explain why a memory-layout change can outperform a clever arithmetic optimization.

If the workload is memory-bound, reducing cache misses, copies, and inefficient access patterns can remove stalls affecting many instructions. Arithmetic savings matter less when execution waits for data.

Exercise 7.8

A teammate proposes an optimization you think is wrong. How do you handle it?

State the technical concern, propose a measurable experiment, agree on correctness/performance criteria, test together, and follow evidence. Preserve team trust and ownership rather than arguing from authority.
