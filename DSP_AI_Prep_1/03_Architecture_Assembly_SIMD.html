Exercise 3.1

A scalar loop does 8 independent float multiplies per iteration. Why might SIMD help? What can prevent a speedup?

SIMD can perform multiple multiplies in one vector instruction, reducing instruction count. Speedup may be limited by memory bandwidth, unaligned or irregular accesses, dependencies, loop overhead, insufficient vector width utilization, instruction scheduling, or other surrounding work. Measure rather than assume.

Exercise 3.2

What is a loop-carried dependency? Give a DSP example.

A later iteration depends on a value produced by an earlier iteration. Example: acc += x[i]*h[i] uses one accumulator, creating a dependency chain. Multiple partial accumulators can sometimes expose more instruction-level parallelism, though floating-point reassociation can alter numerical results.

2. Assembly literacy

You do not need to memorize an ISA not named in the document. Instead, learn to read the structure of low-level code:

load   r1, [x]
load   r2, [h]
mul    r3, r1, r2
add    acc, acc, r3
add    x, x, stride
add    h, h, stride

Translate it back to C. Then ask: how many loads? stores? arithmetic operations? dependencies? branches? address calculations? Can loads overlap? Can operations vectorize?

Exercise 3.3

A kernel performs 16 FLOPs and loads 64 bytes per output. What kind of question should you ask before trying more arithmetic optimization?

Ask whether the kernel is memory-bound. The arithmetic intensity is 16/64 = 0.25 FLOP/byte before considering cache reuse and stores. If data movement dominates, reducing memory traffic or improving locality may matter more than shaving one arithmetic instruction.

3. SIMD exercise: vector dot product

Start from scalar:

float dot(const float* a, const float* b, int n) {
    float s = 0;
    for (int i=0;i<n;i++) s += a[i]*b[i];
    return s;
}

Design a vector version conceptually: load a vector from a, load a vector from b, multiply, accumulate into a vector accumulator, repeat, horizontal-reduce at the end, then handle the tail. Be ready to discuss alignment, aliasing, vector width, and numerical differences.

Exercise 3.4

Why can two mathematically equivalent floating-point implementations produce different answers?

Floating-point addition is not perfectly associative. Changing operation order changes rounding. SIMD reductions, loop unrolling, fused operations, and compiler transformations can therefore change the last bits—and sometimes accumulated error materially. For an optimized DSP kernel, define an acceptable numerical tolerance and test against it.
