01 — C/C++ Foundations

From variables and pointers to production-grade low-level kernel thinking

1. C from absolute zero

Core mental model: a C program manipulates values stored in memory. A variable has a type, a size, an address, and a value. A pointer stores an address. An array is a contiguous sequence of elements. A function receives arguments and can return a value.

English

For DSP kernels, the important question is often not “what does this expression mean?” but “what memory does it touch, how often, and in what order?”

עברית

ב-DSP השאלה החשובה היא לא רק “מה הביטוי מחשב?”, אלא גם “איזה זיכרון הוא ניגש אליו, כמה פעמים, ובאיזה סדר?”.

#include <stddef.h>
float dot(const float* x, const float* h, size_t n) {
    float acc = 0.0f;
    for (size_t i = 0; i < n; ++i)
        acc += x[i] * h[i];
    return acc;
}

Read it slowly: const float* means the function reads floats through a pointer without modifying them. n is the number of elements. The loop performs multiply-accumulate work.

2. Memory and pointers

  • Stack: typically automatic storage for local objects.
  • Heap: dynamically allocated storage with explicit lifetime management in C.
  • Static/global storage: lifetime usually spans the program.
  • Pointer arithmetic is scaled by the pointed-to type.
  • Undefined behavior means the language no longer guarantees what happens.

Exercise 1.1

What is the difference between int *p, int x[10], and int *p = x?

x is an array object containing 10 ints. In most expressions it converts to a pointer to its first element. p is a pointer variable. After int *p = x, p points at x[0]. But an array is not itself a pointer: sizeof(x) is the whole array size, while sizeof(p) is the pointer size.

Exercise 1.2

Find the bug: float* make_buffer(size_t n){ float x[1024]; return x; }

x has automatic storage duration and ceases to exist when the function returns. Returning its address creates a dangling pointer. Safer alternatives include caller-provided storage, static storage where appropriate, or dynamic allocation with a clearly defined owner.

Exercise 1.3

Write a C function that reverses an array in-place. Then state its time and extra-space complexity.

void reverse(int *a, size_t n) {
    for (size_t i = 0; i < n/2; ++i) {
        int t = a[i];
        a[i] = a[n-1-i];
        a[n-1-i] = t;
    }
}

Time O(n), extra space O(1).

3. C++ for DSP/embedded interviews

Know the distinction between value semantics and ownership. Understand constructors/destructors, RAII, references, const-correctness, templates, move semantics, smart pointers, containers, iterators, algorithms, and basic concurrency.

class Buffer {
public:
    explicit Buffer(size_t n) : data_(n) {}
    float* data() { return data_.data(); }
    const float* data() const { return data_.data(); }
private:
    std::vector<float> data_;
};

For low-level code, be able to discuss abstraction cost: an abstraction is acceptable when the compiler can remove its overhead or when its engineering value outweighs the cost. Do not claim “C++ is slow” or “STL is slow” as blanket statements.

Exercise 1.4

Why is const float* x useful in an API?

It documents that the function only reads through x and lets the compiler diagnose accidental writes through that pointer. It improves API clarity and can enable compiler reasoning. It does not by itself make the pointed-to memory immutable globally.

Exercise 1.5

Explain RAII in Hebrew, then in English, as if asked by an interviewer.

עברית: RAII הוא עיקרון שבו משאב קשור לאורך החיים של אובייקט. הקונסטרקטור רוכש/מאתחל את המשאב וה-destructor משחרר אותו, כך שגם במסלולי יציאה שונים ניהול המשאב מסודר.
English: RAII ties resource lifetime to object lifetime. Construction acquires or establishes the resource; destruction releases it, making cleanup deterministic and reducing leak-prone manual control.

Exercise 1.6

Implement a dot product and list at least five ways to optimize it without changing the mathematical result.

  1. Ensure contiguous/aligned data where applicable.
  2. Use a suitable compiler optimization level.
  3. Reduce unnecessary loads/stores.
  4. Use SIMD/vector instructions where the target supports them.
  5. Unroll carefully if it helps instruction scheduling.
  6. Consider multiple accumulators to reduce dependency chains.
  7. Measure cache/memory behavior.

Always validate numerical correctness and benchmark on the target architecture.
