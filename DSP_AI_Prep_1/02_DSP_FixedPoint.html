02 — DSP, Numerical Methods & Fixed Point

Signals → filters → FFT → quantization → implementation

1. Sampling and discrete-time signals

A discrete-time signal is a sequence x[n]. Sampling a continuous signal at rate Fs creates discrete samples. Nyquist reasoning: a band-limited signal needs a sampling rate greater than twice its highest frequency to avoid ideal aliasing.

Interview habit: always track units: Hz, samples, seconds, cycles/sample, radians/sample.

2. Convolution

For an FIR filter:

y[n] = Σ(k=0..M-1) h[k] x[n-k]

This is the archetypal DSP kernel: repeated loads, multiply-accumulate operations, predictable loops, and opportunities for SIMD/unrolling.

Exercise 2.1

For a 64-tap FIR processing 48 kHz mono audio, how many multiply operations per second are required (ignoring boundary effects)?

64 multiplications/sample × 48,000 samples/s = 3,072,000 multiplications/s. If each output also has 64 additions, there are roughly the same order of additions. The point is to translate algorithmic complexity into a workload.

Exercise 2.2

Why can an FIR be easier to optimize than a general recursive filter?

An FIR has a finite, feed-forward dependency pattern. Each output depends on a fixed window of input samples and coefficients. An IIR introduces feedback, so future outputs depend on previous outputs, creating stronger loop-carried dependencies and potentially more numerical sensitivity.

3. Frequency-domain thinking

Know the DFT definition conceptually and why FFT algorithms reduce the direct DFT's O(N²) work to roughly O(N log N). Understand complex numbers, magnitude/phase, bins, windowing, leakage, and the difference between a spectrum and a PSD estimate.

Exercise 2.3

Explain why windowing can reduce spectral leakage but also changes the effective spectral response.

Finite observation truncates a signal in time, which corresponds to convolution with the window spectrum in frequency. A tapered window reduces sidelobes, decreasing leakage into distant bins, but widens the main lobe and therefore reduces frequency resolution. The trade-off is fundamental.

4. Fixed-point arithmetic — חובה

Suppose an integer stores a real value using scale S. A simple model is:

real_value = integer_value / S

In Q-format, the number of fractional bits defines S = 2^F. For Q1.15, an int16 typically represents a signed fractional range near [-1,1) with scale 2^15.

Multiplication is the dangerous step: multiplying two Q1.15 integers produces a wider product with twice the fractional-bit count. You must rescale, round, and handle saturation/overflow deliberately.

Exercise 2.4

Two Q1.15 numbers are 0.5 and 0.25. What integer representations do they have, and what happens after integer multiplication?

0.5 × 32768 = 16384; 0.25 × 32768 = 8192. Their raw integer product is 16384×8192 = 134,217,728. That product has 30 fractional bits, not 15. To return to Q1.15 you shift right by 15 (with an appropriate rounding policy), obtaining 4096, which represents 0.125.

Exercise 2.5

What is saturation and why is wraparound dangerous in DSP?

With saturation, an out-of-range result is clamped to the representable maximum/minimum. With two's-complement wraparound, overflow can jump from a large positive number to a large negative number. In a signal-processing pipeline this can create severe distortion or destabilize an algorithm, especially in feedback systems.

Exercise 2.6

Design a fixed-point FIR accumulator strategy. What width would you consider and why?

Start from coefficient/input bit widths and the number of summed products. Each multiplication needs a wider intermediate. The accumulator must have enough headroom for worst-case sum magnitude, often adding guard bits related to the number of taps. Then explicitly define rounding and final saturation. The exact width depends on signal bounds, coefficient bounds, and implementation requirements; never choose it blindly.

5. DSP coding drill

float fir(const float *x, const float *h, int taps) {
    float y = 0;
    for (int k=0; k<taps; ++k)
        y += x[k] * h[k];
    return y;
}

Be ready to transform this baseline into: (1) safe production C, (2) fixed point, (3) SIMD/vectorized form, (4) a cache-friendly version, and (5) a version with measured performance.
