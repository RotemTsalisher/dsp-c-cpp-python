Exercise 5.1

Why is a matched filter useful at the receiver?

For a known pulse shape in additive white Gaussian noise, the matched filter maximizes the signal-to-noise ratio at the sampling instant under the usual assumptions. In implementation terms, it is closely related to correlation/convolution with a time-reversed/conjugated pulse.

Exercise 5.2

What is the difference between SNR and BER?

SNR is a signal-to-noise power ratio. BER is the fraction/probability of transmitted bits that are detected incorrectly. A communication system maps channel conditions and receiver design into an error probability; the relationship depends on modulation, coding, synchronization, etc.

2. Neural-network graphs

The role lists good understanding of machine learning and neural-network graphs as an advantage. fileciteturn0file0L30-L31

Think of a graph as operators connected by tensors. Example:

Input → Conv → ReLU → Conv → Add(skip) → ReLU → Output

For inference optimization, ask: tensor shapes? memory layout? operator cost? reuse? quantization? fusion opportunities? parallelism? bandwidth? intermediate-buffer lifetime?

Exercise 5.3

Why can operator fusion speed up neural-network inference even when the arithmetic count barely changes?

Fusion can eliminate intermediate memory writes/reads, reduce kernel-launch or dispatch overhead, improve locality, and keep values in registers/cache longer. The gain can come from data movement and overhead rather than fewer mathematical operations.

Exercise 5.4

Explain quantized inference and its connection to fixed-point DSP.

Quantized inference represents tensors/weights using lower-precision numeric formats, often integer-based. This can reduce memory footprint and accelerate inference on suitable hardware, but requires scale/zero-point or other calibration and introduces quantization error. The conceptual bridge to fixed-point DSP is explicit numerical representation and careful management of range, precision, rounding, and saturation.

3. End-to-end optimization challenge

Imagine a neural-network layer takes 5 ms but your real-time budget is 3 ms. You are not allowed to change the model's output tolerance. Walk through your response:

  1. Define exact input/output and correctness metric.
  2. Profile: where are the 5 ms spent?
  3. Check memory bandwidth/cache behavior.
  4. Check SIMD/vectorization and kernel implementation.
  5. Check layout and copies.
  6. Consider operator fusion.
  7. Consider quantization only if accuracy permits.
  8. Measure each change.
  9. Validate worst-case latency, not only average.

Exercise 5.5

Give a bilingual 60-second answer to: “How would you optimize an ML inference workload on a DSP?”

English

I would first establish a correct baseline and profile it on the target platform. I would identify whether the bottleneck is compute, memory movement, synchronization, or operator overhead. Then I would optimize the hottest kernels using appropriate vectorization and data layout, look for fusion and buffer reuse, and consider quantization if the accuracy budget allows it. After every change I would run numerical correctness tests and measure latency, throughput, memory, and—where relevant—power. I would optimize for the actual real-time constraint, not just average benchmark speed.

עברית

קודם אגדיר baseline נכון ואבצע profiling על הפלטפורמה הרלוונטית. אזהה האם צוואר הבקבוק הוא חישוב, תעבורת זיכרון, סנכרון או overhead של operators. לאחר מכן אופטמז את ה-kernels החמים באמצעות vectorization ו-data layout, אבדוק fusion ו-buffer reuse, ואשקול quantization רק אם תקציב הדיוק מאפשר זאת. אחרי כל שינוי אבצע בדיקות נכונות ומדידות של latency, throughput, memory ובמידת הצורך power.
