06 — Mock Interview & Oral Defense

Timed questions for the actual interview

Interview simulation rules

Do these without notes. Give yourself 20–30 seconds to structure the answer. If coding, first state the algorithm, complexity, edge cases, then code.

Golden response structure: clarify → baseline → correctness → complexity → bottleneck → optimization → measurement → trade-offs.

Exercise 6.1

C pointers
Explain pointer vs array. Then explain const int*, int* const, and const int* const.

Pointer/array distinction; read-only pointee; const pointer; both const.

Exercise 6.2

Memory
A DSP kernel gets slower when input grows from 32 KB to 4 MB. Give hypotheses.

Cache capacity/locality, memory bandwidth, working-set changes, TLB/page effects, other system effects.

Exercise 6.3

SIMD
Explain vectorization to a non-specialist and then to a DSP engineer.

One instruction handles multiple independent data elements; discuss vector width, loads, dependencies, tail.

Exercise 6.4

Fixed point
Why does multiplication require special care in Q-format?

Fractional bits double in the raw product; need wider intermediate and rescaling/rounding/saturation.

Exercise 6.5

Real time
Is 99th-percentile latency enough for a hard real-time deadline?

Not necessarily; need worst-case/bounded behavior and scheduling/jitter analysis.

Exercise 6.6

Profiling
The profiler says a function is 40% of runtime. Should you optimize it?

First determine if it is the true constrained bottleneck and whether optimization affects the relevant metric; Amdahl's law gives an upper bound.

Exercise 6.7

Amdahl
If 50% of runtime is improved by 4×, what is the maximum total speedup?

1/(0.5+0.5/4)=1.6×.

Exercise 6.8

Communications
Why does synchronization matter before BER optimization?

Timing/carrier errors can dominate errors; a theoretically good detector fails if sampling phase/frequency/phase is wrong.

Exercise 6.9

ML graph
What does a tensor layout change buy you?

Better contiguous access, SIMD-friendly dimensions, fewer transposes/copies, better cache behavior.

Exercise 6.10

Behavioral
Tell me about a difficult optimization problem.

Use STAR; quantify problem, constraints, investigation, action, measurement, trade-off, result, lesson.

Rapid-fire round — no solution shown until after your attempt

  1. What is undefined behavior?
  2. Why can memcpy be faster than a loop?
  3. What is aliasing?
  4. Why does branch predictability matter?
  5. What is temporal locality?
  6. What is an instruction dependency?
  7. What is saturation?
  8. What is quantization error?
  9. What is BER?
  10. What is a convolution?
  11. Why FFT instead of direct DFT?
  12. Latency vs throughput?
  13. What does profiling measure?
  14. How do you test numerical equivalence?
  15. What makes an optimization unsafe?
  1. Behavior where the language imposes no requirements.
  2. Library/compiler can use optimized implementation and hardware instructions; not guaranteed in every case.
  3. Pointer/reference rules that affect whether two accesses may refer to the same object.
  4. Mispredictions disrupt instruction flow.
  5. Reuse of recently accessed data.
  6. One instruction/result must wait for another.
  7. Clamp rather than wrap on overflow.
  8. Error from finite representation.
  9. Bit error rate.
  10. Weighted sum over shifted sequences.
  11. Lower asymptotic computational complexity.
  12. Time for one result vs amount of work per unit time.
  13. Evidence about where time/resources are spent.
  14. Reference outputs + tolerances/property tests.
  15. If it violates correctness, deadline, memory, power, safety, or maintainability requirements.
