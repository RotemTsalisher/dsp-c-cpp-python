Advanced C++: Array Decay & Template Reference Deduction

Engineering Curriculum - Module 4: High-Reliability Embedded Code

1. The Problem: What is "Array Decay"?

In 2nd-year EE studies, you've likely used C-style arrays frequently. However, C-style arrays have a hidden "identity crisis" when passed into functions.

Theory: Pointer Decay

When you pass an array (e.g., double sig[10]) into a function, it does not pass the array object. Instead, it "decays" into a pointer to its first element.
The Trap: Inside a function that receives an array, the sizeof() operator will return the size of the pointer (usually 4 or 8 bytes), NOT the size of the array. 
void processSignal(double sig[]) {
    // sig is now just a double*
    // We have lost the knowledge that there were 10 elements!
    size_t size = sizeof(sig); // Returns 8 on 64-bit systems
}

2. The Junior Level: Manual Size Passing

The standard "Tinker Level" fix is to pass a second argument for size. This is what you see in most Arduino or Legacy C code.

void processSignal(double* sig, size_t n) {
    for(size_t i = 0; i < n; ++i) {
        // Safe, but requires the programmer to never make a mistake
    }
}
Tinker Warning: This relies on the human to pass the correct size. If you pass an array of size 5 but tell the function it's size 10, the system will read "garbage" memory or crash.

3. The Expert Level: Reference to Array Deduction

In Modern C++, we can use Templates to force the compiler to count the array for us. This is the "Turn-Key Solution" standard expected at companies like Trego.

Theory: T (&sig)[N]

By using a reference to an array, we prevent the decay. The compiler deduces two things:
  1. T: The type of data (int, double, float).
  2. N: The exact number of elements in the array.
template <typename T, size_t N>
void printSignal(T (&sig)[N]) {
    // N is now a compile-time constant.
    // We can use it safely in loops or static_asserts!
    std::cout << "Processing " << N << " samples." << std::endl;

    for(size_t i = 0; i < N; ++i) {
        std::cout << sig[i] << " ";
    }
}

Why is this superior?

  • No Memory Overhead: N is not stored in RAM; it is baked into the code by the compiler.
  • Range-Based Loops: Because the array hasn't decayed, for(auto x : sig) works perfectly!
  • Type Safety: You cannot accidentally pass a single pointer to this function; it must be an actual array.

4. Advanced: Compile-Time Branching

Sometimes you want to handle pointers and arrays in the same function. We use if constexpr (C++17) to make decisions while the code is compiling.

template <typename S>
void smartPrint(S& sig) {
    if constexpr (std::is_array_v<S>) {
        std::cout << "Array detected! Size: " << std::extent_v<S> << std::endl;
    } else {
        std::cout << "Standard variable detected." << std::endl;
    }
}

5. Practice Exercises

Exercise 1

The Buffer Overflow Guard

Write a template function sumArray that accepts a reference to an array of any numeric type. Use static_assert to ensure the array has at least 2 elements before performing any math.

template <typename T, size_t N>
T sumArray(T (&arr)[N]) {
    static_assert(N >= 2, "Array too small for processing!");
    T total = 0;
    for(const auto& val : arr) total += val;
    return total;
}
Exercise 2

EE Application: Moving Average

Create a template function that accepts an array of signal data by reference and returns the average. Ensure the function works for float, double, and int arrays.

template <typename T, size_t N>
double getAverage(T (&arr)[N]) {
    double sum = 0;
    for(size_t i = 0; i < N; ++i) {
        sum += arr[i];
    }
    return sum / N; // N is perfectly known
}
