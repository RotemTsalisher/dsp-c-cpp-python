Exercise 1 — Warm-up

Context: A front-end scales raw ADC counts to volts before PSD estimation.

Implement a plain function countsToVolts(double counts, double fullScaleVolts, int resolutionBits) that returns counts / (2^resolutionBits - 1) * fullScaleVolts.

Overload the name countsToVolts with a second version that takes (double countsLeft, double countsRight, double fullScaleVolts, int resolutionBits) and returns the mono mix 0.5 * (L + R) after conversion (still a single double).

Topics: functions; function overloading.

// g++ -std=c++20 -Wall -Wextra -O2 -pedantic
#include <cstdint>
#include <cmath>

double countsToVolts(double const counts, double const fullScaleVolts, int const resolutionBits)
{
    double const denom = std::ldexp(1.0, resolutionBits) - 1.0;
    return (counts / denom) * fullScaleVolts;
}

double countsToVolts(double const countsLeft, double const countsRight,
                     double const fullScaleVolts, int const resolutionBits)
{
    double const monoCounts = 0.5 * (countsLeft + countsRight);
    return countsToVolts(monoCounts, fullScaleVolts, resolutionBits);
}

// Example-only entry (not required for library use)
#if defined(DSP_DEMO_MAIN)
int main()
{
    double const v = countsToVolts(2047.0, 2.5, 12);
    double const m = countsToVolts(1000.0, 3000.0, 2.5, 12);
    (void)v;
    (void)m;
    return 0;
}
#endif
Why these features: Overloading keeps one technical name (countsToVolts) while selecting mono vs stereo preprocessing. ldexp avoids relying on integer pow for the denominator and stays numerically stable for typical ADC bit widths.
Exercise 2

Context: Fixed-point audio samples are promoted to double for analysis.

Write a function template promoteToDouble(T value) that returns static_cast<double>(value). Add a template specialization for bool that maps false to 0.0 and true to 1.0 (gate line).

Add a requires clause so the primary template only instantiates for arithmetic types (use std::is_arithmetic_v<T>). The bool specialization does not use that constraint.

Topics: function templates; template specialization; requires.

#include <type_traits>

template <typename T>
requires std::is_arithmetic_v<T>
constexpr double promoteToDouble(T const value)
{
    return static_cast<double>(value);
}

template <>
constexpr double promoteToDouble<bool>(bool const value)
{
    return value ? 1.0 : 0.0;
}
Why these features: requires keeps mistaken instantiations (for example user-defined types) from silently compiling. Explicit specialization handles bool as a gate signal without treating it as a numeric promotion.
Exercise 3

Context: A comb-style delay path compares a tap against a noise floor.

Define a non-template function bool exceedsFloor(double sample, double (*predicate)(double)) that returns predicate(sample) interpreted as true if nonzero.

In main (or a test harness), pass a lambda by first storing it in a named variable, then obtain a function pointer only if you can justify the conversion; otherwise wrap the lambda in a named free function and pass that address to document static dispatch. Implement static bool noiseFloorPredicate(double x) that returns (x > floor) with floor captured by making it a constexpr threshold inside the function for this exercise.

Topics: lambda functions; function pointers; passing functions as arguments (no std::function).

#include <cstddef>

bool exceedsFloor(double const sample, bool (*predicate)(double))
{
    return predicate(sample);
}

static bool noiseFloorPredicate(double const x)
{
    static constexpr double floor = 1.0e-6;
    return x > floor;
}

int main()
{
    double const tap = 3.5e-5;
    bool const hot = exceedsFloor(tap, &noiseFloorPredicate);
    (void)hot;
    return 0;
}
Why these features: A formal pointer type bool (*)(double) documents the ABI-level callback without pulling in STL function wrappers. A named static predicate keeps the address stable for teaching static dispatch; a stateful lambda would require a different interface (not required here).
Exercise 4

Context: A quick PSD panel sums narrowband energy estimates at compile time where possible.

Write a variadic function template constexpr double sumBands(double... bands) that uses a fold expression to sum an arbitrary number of double arguments. Write constexpr double averageBands(double... bands) that divides the fold-sum by sizeof...(bands) (guard zero-size packs with static_assert in the function body).

Add constexpr double nyquistHz(double sampleRate) and use it only at compile time to initialize a constexpr object in an anonymous namespace.

Topics: fold expressions and parameter packs; constexpr.

#include <type_traits>

namespace
{
    constexpr double nyquistHz(double const sampleRate)
    {
        return 0.5 * sampleRate;
    }

    constexpr double kNyquist_48k = nyquistHz(48000.0);
}

template <typename... Ts>
constexpr double sumBands(Ts const... bands)
{
    static_assert((std::is_same_v<Ts, double> && ...));
    return (bands + ... + 0.0);
}

template <typename... Ts>
constexpr double averageBands(Ts const... bands)
{
    static_assert(sizeof...(bands) > 0);
    static_assert((std::is_same_v<Ts, double> && ...));
    return sumBands(bands...) / static_cast<double>(sizeof...(bands));
}

static_assert(averageBands(1.0, 3.0, 5.0) == 3.0);
static_assert(kNyquist_48k == 24000.0);
Why these features: Fold expressions give a single idiomatic sum over a parameter pack. constexpr lets the compiler prove simple spectral bookkeeping without runtime cost. Include <type_traits> for the pack checks if you extend the snippet.
Exercise 5

Context: Register fields share one 32-bit word on a DSP peripheral.

Introduce a namespace dsp::afe. Inside it, define a variable template trait template<typename T> inline constexpr bool is_register_word_v = std::is_same_v<T, std::uint32_t>;

Provide a function template constexpr std::uint32_t maskedWrite(std::uint32_t word, std::uint32_t mask, T field) that is constrained by a C++20 concept requiring is_register_word_v<T> plus that T is an integral type. Apply the mask, OR in the field, return the updated word.

Topics: traits via variable templates; namespaces; concepts and type-constrained templates.

#include <cstdint>
#include <type_traits>

namespace dsp::afe
{
template <typename T>
inline constexpr bool is_register_word_v = std::is_same_v<T, std::uint32_t>;

template <typename T>
concept RegisterWord = std::is_integral_v<T> && is_register_word_v<T>;

template <RegisterWord T>
constexpr std::uint32_t maskedWrite(std::uint32_t const word, std::uint32_t const mask, T const field)
{
    return (word & ~mask) | (static_cast<std::uint32_t>(field) & mask);
}
}

static_assert(dsp::afe::maskedWrite(0xFFFF'0000u, 0x0000'FFFFu, 0x0A0Au) == 0xFFFF'0A0Au);
Why these features: Variable templates express portable traits without macros. A named concept keeps register updates readable and fails early if someone passes a wrong-width word type.
Exercise 6

Context: A capture buffer holds interleaved samples for a Hann window step.

Design a class InterleavedCapture in a header/source split described in the solution: public interface for allocation, private buffer pointer, destructor frees memory, constructor takes channel count and frame count (product gives sample count). Provide accessors; avoid STL containers: use new double[] / delete[].

Demonstrate managing an object through a pointer (InterleavedCapture*) in example code. Mention include guards in the header comment.

Topics: class introduction; encapsulation; constructors; spreading across files (described); include guards (described); pointers to class objects; destructors.

Multi-file layout (production): InterleavedCapture.h uses #ifndef INTERLEAVED_CAPTURE_H / #define / #endif include guards (or #pragma once if your toolchain allows). Implementation lives in InterleavedCapture.cpp.

// ---- InterleavedCapture.h (sketch) ----
#ifndef INTERLEAVED_CAPTURE_H
#define INTERLEAVED_CAPTURE_H

#include <cstddef>

class InterleavedCapture
{
public:
    InterleavedCapture(int channels, std::size_t frames);
    ~InterleavedCapture();

    InterleavedCapture(InterleavedCapture const&) = delete;
    InterleavedCapture& operator=(InterleavedCapture const&) = delete;

    std::size_t sampleCount() const;
    double& at(std::size_t index);
    double const& at(std::size_t index) const;

private:
    int const channels_;
    std::size_t const frames_;
    std::size_t const samples_;
    double* buffer_;
};

#endif

// ---- InterleavedCapture.cpp ----
#include "InterleavedCapture.h"
#include <new>
#include <stdexcept>

InterleavedCapture::InterleavedCapture(int const channels, std::size_t const frames)
    : channels_{channels}
    , frames_{frames}
    , samples_{static_cast<std::size_t>(channels) * frames}
    , buffer_{nullptr}
{
    if (channels <= 0) {
        throw std::invalid_argument("channels");
    }
    buffer_ = new double[samples_]{};
}

InterleavedCapture::~InterleavedCapture()
{
    delete[] buffer_;
}

std::size_t InterleavedCapture::sampleCount() const
{
    return samples_;
}

double& InterleavedCapture::at(std::size_t const index)
{
    return buffer_[index];
}

double const& InterleavedCapture::at(std::size_t const index) const
{
    return buffer_[index];
}
Why these features: A class bundles invariant checks with resource ownership. Explicit destructor teaching pairs naturally with raw allocation before smart pointers appear in a later course stage. Deleted copy operations avoid double-free until rule-of-five teaching is complete.
Exercise 7 — Integration

Context: A background worker integrates a short chunk of PSD bins while the foreground thread prepares the next FFT window.

Using <thread>, spawn a thread that computes sumBands (from Exercise 4 style) over exactly three double literals passed as arguments to the thread function. The foreground thread must join() before exit. Keep all storage in fixed double variables or a small stack array—no STL containers.

Wrap the worker entry in namespace dsp::workers. Use a named function void integrateTriple(double a, double b, double c, double& out) for the body.

Topics: <thread> basics; namespaces; constexpr/fold review inside the worker.

#include <thread>

template <typename... Ts>
constexpr double sumBands(Ts const... bands)
{
    return (bands + ... + 0.0);
}

namespace dsp::workers
{
void integrateTriple(double const a, double const b, double const c, double& out)
{
    out = sumBands(a, b, c);
}
}

int main()
{
    double result = 0.0;
    std::thread worker([&result]() {
        dsp::workers::integrateTriple(0.25, 0.50, 0.125, result);
    });

    worker.join();
    return result > 0.0 ? 0 : 1;
}
Why these features: std::thread with join documents lifetime coupling to the output slot. The lambda here only forwards to a function pointer–compatible free function; production code would factor threading policy out of DSP math.
