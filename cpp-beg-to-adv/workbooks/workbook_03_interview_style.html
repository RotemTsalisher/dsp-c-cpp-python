Question 1

“You have two ADC paths that both produce a PSD bin as double. How do you share one function name but keep compile-time type checks for integer versus floating accumulators?”

Answer with overloaded free functions plus a constrained template using requires (no STL containers). Frame the example as summing narrowband energy contributions.

Touches: overloading; templates; requires.

#include <type_traits>

double accumulateBin(double const a, double const b)
{
    return a + b;
}

int accumulateBin(int const a, int const b)
{
    return a + b;
}

template <typename T>
requires std::is_floating_point_v<T>
constexpr T accumulateBin(T const a, T const b)
{
    return a + b;
}
Why: Overloading handles the non-template double path explicitly; the constrained template documents that only floating policies participate in the generic lane, catching mistaken integer use at compile time.
Question 2

“Explain how you would pass a gain stage into a sample routine without std::function.”

Provide a typedef for double (*GainFn)(double) and a function double applyStage(double x, GainFn fn). Add a second path that accepts a lambda only by wrapping its behavior in a named static function if you need a stable address.

Touches: function pointers; passing functions as arguments; lambdas (as factories of logic, not necessarily stored).

using GainFn = double (*)(double);

double applyStage(double const x, GainFn fn)
{
    return fn(x);
}

static double sixDbBoost(double const x)
{
    return x * 1.99526231497; // ~ +6 dB linear
}

int main()
{
    double const y = applyStage(0.5, &sixDbBoost);
    (void)y;
    return 0;
}
Why: A function pointer type is explicit in mangling and ABI reviews. Teaching code keeps the address stable; lambdas with captures cannot convert to plain GainFn without thunks.
Question 3

“How can you prove a Hann window length at compile time for a fixed FFT, and combine that with a fold expression?”

Write constexpr int hannLength(int order) returning 1 << order, then a variadic constexpr double sumBins(double...) using a right fold.

Touches: constexpr; fold expressions and parameter packs.

constexpr int hannLength(int const order)
{
    return 1 << order;
}

template <typename... Ts>
constexpr double sumBins(Ts... values)
{
    return (values + ... + 0.0);
}

static_assert(hannLength(10) == 1024);
static_assert(sumBins(1.0, 2.0, 3.0) == 6.0);
Why: constexpr lets the compiler verify FFT sizing. Folds express the energy sum without manual recursion for teaching clarity.
Question 4

“You must log PSD slices from a worker thread while the UI thread prints status. What is the minimal <thread> usage you expect in production review?”

Show construction with a free function target, join() before reading shared scalar results, and a namespace dsp::trace wrapping the worker entry. No containers.

Touches: threads; namespaces.

#include <thread>

namespace dsp::trace
{
void logSlice(double const psdValue, double& sink)
{
    sink = psdValue;
}
}

int main()
{
    double sink = 0.0;
    std::thread worker([&sink]() {
        dsp::trace::logSlice(0.25, sink);
    });

    worker.join();
    return sink > 0.0 ? 0 : 1;
}
Why: Reviewers expect explicit join or detach policy; here join couples lifetime to the scalar sink. The lambda captures the output by reference so no wrapper from <functional> is required.
Question 5

“What is the difference between a variable template trait and a constexpr function when you want to branch on whether a register width is 32-bit?”

Show template<typename T> inline constexpr bool is_word32_v = ... plus a concept that gates a maskedOr helper. Keep the arithmetic in <cstdint>.

Touches: traits via variable templates; concepts.

#include <cstdint>
#include <type_traits>

template <typename T>
inline constexpr bool is_word32_v = std::is_same_v<T, std::uint32_t>;

template <typename T>
concept Word32 = is_word32_v<T>;

template <Word32 T>
constexpr std::uint32_t maskedOr(std::uint32_t const base, std::uint32_t const mask, T const field)
{
    return base | (static_cast<std::uint32_t>(field) & mask);
}
Why: Variable templates read like constexpr values at template scope, which interviewers often contrast with constexpr bool foo() functions. Concepts consume those predicates without macros.
Question 6

“Walk through why a polymorphic audio node needs a virtual destructor when a factory returns IAudioNode*.”

Sketch an interface with a pure virtual process(double), a derived FIR stage, and delete through the base pointer in a commented example. Mention static binding when calling a non-virtual helper on the derived object directly.

Touches: abstract classes; virtual destructor; static binding vs polymorphism.

class IAudioNode
{
public:
    virtual double process(double const sample) = 0;
    virtual ~IAudioNode() = default;
};

class FirStage final : public IAudioNode
{
public:
    double process(double const sample) override
    {
        return sample * 0.5;
    }

    double latencySamples() const
    {
        return 32.0;
    }
};

void demo()
{
    IAudioNode* node = new FirStage{};
    double const y = node->process(1.0);
    delete node; // requires virtual ~IAudioNode
    (void)y;

    FirStage direct{};
    double const lat = direct.latencySamples(); // static binding, no vtable
    (void)lat;
}
Why: Deletion through a base pointer without a virtual destructor is undefined behavior once subclasses own resources. Non-virtual helpers illustrate static binding when the concrete type is known.
Question 7

“How do you implement symmetric operator+ for mono and stereo PSD contributions without duplicating friend declarations everywhere?”

Provide a minimal two-level hierarchy: base holds mono energy, derived adds a right channel. Implement two free operator+ overloads and mark where friendship is required.

Touches: operator overloading with inheritance; encapsulation boundaries.

class MonoPsd
{
public:
    explicit MonoPsd(double const value)
        : value_{value}
    {
    }

    double value() const { return value_; }

    friend MonoPsd operator+(MonoPsd const& a, MonoPsd const& b);

private:
    double value_;
};

class StereoPsd : public MonoPsd
{
public:
    StereoPsd(double const left, double const right)
        : MonoPsd{left}
        , right_{right}
    {
    }

    double right() const { return right_; }

    friend StereoPsd operator+(StereoPsd const& a, StereoPsd const& b);

private:
    double right_;
};

MonoPsd operator+(MonoPsd const& a, MonoPsd const& b)
{
    return MonoPsd{a.value_ + b.value_};
}

StereoPsd operator+(StereoPsd const& a, StereoPsd const& b)
{
    return StereoPsd{a.value() + b.value(), a.right() + b.right()};
}
Why: Symmetric free operators keep commutative intuition for energy sums. Friends stay scoped to the classes that actually need private field access, which is a common whiteboard talking point.
