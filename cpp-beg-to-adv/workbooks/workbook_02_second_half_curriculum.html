Exercise 1 — Warm-up

Context: A fractional delay line stores tap metadata.

Define a struct Tap with public double delaySamples and double gain. Define a class FractionalDelayLine that holds two taps in alignas(16) double taps_[2][2] (interpret as rows: delay, gain) to exercise boundary alignment.

Provide non-static methods FractionalDelayLine& setTap(int index, double delay, double gain) that assign through this and return *this for chaining. Add double const* data() const.

Topics: struct; boundary alignment; this operator and chained calls.

#include <cstddef>

struct Tap
{
    double delaySamples;
    double gain;
};

class FractionalDelayLine
{
public:
    FractionalDelayLine& setTap(int const index, double const delay, double const gain)
    {
        taps_[static_cast<std::size_t>(index)][0] = delay;
        taps_[static_cast<std::size_t>(index)][1] = gain;
        return *this;
    }

    double const* data() const
    {
        return &taps_[0][0];
    }

private:
    alignas(16) double taps_[2][2]{};
};
Why these features: alignas documents SIMD-friendly layout assumptions. Returning *this from a non-static member illustrates how this enables fluent configuration without free helpers.
Exercise 2

Context: A base band stores PSD bin gain; a derived stage applies a comb notch.

Create class SpectrumBandBase with a protected double gain_, constructor taking gain, and virtual double process(double psdBin) const returning gain_ * psdBin.

Derive class CombNotchBand : public SpectrumBandBase. Override process to subtract a fixed notch depth from the scaled bin (model as gain_ * psdBin - notchDepth_). Mark overrides explicitly. Demonstrate const-correct accessors for read-only gain.

Topics: inheritance and method overriding; protected members; const correctness; virtual keyword (first pass).

class SpectrumBandBase
{
public:
    explicit SpectrumBandBase(double const gain)
        : gain_{gain}
    {
    }

    virtual double process(double const psdBin) const
    {
        return gain_ * psdBin;
    }

    double gain() const
    {
        return gain_;
    }

    virtual ~SpectrumBandBase() = default;

protected:
    double gain_;
};

class CombNotchBand final : public SpectrumBandBase
{
public:
    CombNotchBand(double const gain, double const notchDepth)
        : SpectrumBandBase{gain}
        , notchDepth_{notchDepth}
    {
    }

    double process(double const psdBin) const override
    {
        return SpectrumBandBase::process(psdBin) - notchDepth_;
    }

private:
    double notchDepth_;
};
Why these features: virtual establishes dynamic dispatch for PSD shaping. override catches signature drift. const member functions document read-only observers on signal objects.
Exercise 3

Context: Calibration bypasses normal gain privacy for factory trim only.

Extend the hierarchy: class SpectrumBandBase keeps gain_ protected. Add a derived class TrimmedBand : public SpectrumBandBase that declares friend void factoryCalibrate(TrimmedBand& band, double newGain);. Implement the friend to assign band.gain_ directly.

In another derived type (or the same file), use using SpectrumBandBase::gain_; in a struct DiagnosticView : public SpectrumBandBase to resurrect direct member access at public for a lab-only build—document why this is unsafe for production.

Topics: friend in inheritance; resurrecting member access with using; base-class access discipline.

class SpectrumBandBase
{
public:
    explicit SpectrumBandBase(double const gain)
        : gain_{gain}
    {
    }

    virtual ~SpectrumBandBase() = default;

protected:
    double gain_;
};

class TrimmedBand : public SpectrumBandBase
{
    friend void factoryCalibrate(TrimmedBand& band, double newGain);

public:
    explicit TrimmedBand(double const gain)
        : SpectrumBandBase{gain}
    {
    }
};

void factoryCalibrate(TrimmedBand& band, double const newGain)
{
    band.gain_ = newGain;
}

struct DiagnosticView : public SpectrumBandBase
{
    using SpectrumBandBase::gain_;

    explicit DiagnosticView(double const gain)
        : SpectrumBandBase{gain}
    {
    }
};

// DiagnosticView exposes gain_ publicly via using — convenient for a lab harness,
// but breaks encapsulation if shipped.
Why these features: friend localizes privileged writes for calibration. using adjusts access level deliberately when a diagnostic type is compiled only in test builds.
Exercise 4

Context: Copying a filter bank must duplicate gains safely.

Implement class BiquadCoefficients with double b0_, b1_, b2_ and a copy constructor that duplicates fields. Derive class BankStage : public BiquadCoefficients holding an extra double stageGain_. Write the copy constructor for BankStage that forwards base-class copying.

Also define a small helper class ChannelMeter (not necessarily derived from BiquadCoefficients) that stores a const data member double const offset_ and a reference member double const& zeroRef_ bound in the constructor initializer list. Provide double normalize(double sample) const as sample - zeroRef_ + offset_.

Topics: copy constructors and inheritance; const member variables and reference member variables; const correctness on accessors.

class BiquadCoefficients
{
public:
    BiquadCoefficients(double const b0, double const b1, double const b2)
        : b0_{b0}
        , b1_{b1}
        , b2_{b2}
    {
    }

    BiquadCoefficients(BiquadCoefficients const& other) = default;

    double b0() const { return b0_; }
    double b1() const { return b1_; }
    double b2() const { return b2_; }

private:
    double b0_;
    double b1_;
    double b2_;
};

class BankStage : public BiquadCoefficients
{
public:
    BankStage(double const b0, double const b1, double const b2, double const stageGain)
        : BiquadCoefficients{b0, b1, b2}
        , stageGain_{stageGain}
    {
    }

    BankStage(BankStage const& other)
        : BiquadCoefficients{other}
        , stageGain_{other.stageGain_}
    {
    }

    double stageGain() const { return stageGain_; }

private:
    double stageGain_;
};

class ChannelMeter
{
public:
    ChannelMeter(double const offset, double const& liveZero)
        : offset_{offset}
        , zeroRef_{liveZero}
    {
    }

    double normalize(double const sample) const
    {
        return sample - zeroRef_ + offset_;
    }

private:
    double const offset_;
    double const& zeroRef_;
};
Why these features: Delegating to the base copy subobject keeps invariants aligned when stages are duplicated for multirate banks. Const and reference members force explicit initialization and model a live calibration anchor without copying it.
Exercise 5

Context: A measurement pipeline exposes one polymorphic entry point.

Define an abstract interface class ISpectrumMetric with virtual double evaluate(double const* bins, int count) const = 0; and a protected non-virtual default constructor. Provide virtual ~ISpectrumMetric() = default;.

Implement class TotalEnergy final : public ISpectrumMetric that sums bins. Implement class PeakHold final : public ISpectrumMetric that returns the maximum.

Write a function double dispatchMetric(ISpectrumMetric const& metric, double const* bins, int count) showing dynamic binding. Write a second overload double dispatchMetric(TotalEnergy const& metric, ...) that calls metric.evaluate directly to illustrate static binding when the concrete type is known.

Topics: abstract classes; pure virtual functions; polymorphism at different levels; static binding vs virtual dispatch.

class ISpectrumMetric
{
public:
    virtual double evaluate(double const* bins, int count) const = 0;
    virtual ~ISpectrumMetric() = default;

protected:
    ISpectrumMetric() = default;
};

class TotalEnergy final : public ISpectrumMetric
{
public:
    double evaluate(double const* bins, int const count) const override
    {
        double acc = 0.0;
        for (int i = 0; i < count; ++i) {
            acc += bins[i];
        }
        return acc;
    }
};

class PeakHold final : public ISpectrumMetric
{
public:
    double evaluate(double const* bins, int const count) const override
    {
        double peak = bins[0];
        for (int i = 1; i < count; ++i) {
            if (bins[i] > peak) {
                peak = bins[i];
            }
        }
        return peak;
    }
};

double dispatchMetric(ISpectrumMetric const& metric, double const* bins, int const count)
{
    return metric.evaluate(bins, count);
}

double dispatchMetric(TotalEnergy const& metric, double const* bins, int const count)
{
    return metric.evaluate(bins, count);
}
Why these features: Pure virtuals define a narrow contract for EE metrics. Overloading dispatchMetric shows how static resolution avoids vtable indirection when the concrete type is fixed at compile time.
Exercise 6

Context: A leaf analyzer must not be subclassed further; a base helper carries a default level offset.

Declare class NarrowbandAnalyzer final : public ISpectrumMetric (reuse the interface from Exercise 5 sketch) implementing evaluate as the average bin. In an abstract base class LevelAdjustedMetric : public ISpectrumMetric, add virtual double evaluate(double const* bins, int count) const override that applies virtual double levelOffset() const = 0;.

Add virtual double evaluate(double const* bins, int count, bool applyOffset) const with default argument applyOffset = true in LevelAdjustedMetric. Demonstrate that the default is bound statically for a pointer to LevelAdjustedMetric versus dynamically when called through ISpectrumMetric const* (commentary in solution).

Topics: final; virtual override with default arguments; overload vs override vs name hiding (commentary).

class ISpectrumMetric
{
public:
    virtual double evaluate(double const* bins, int count) const = 0;
    virtual ~ISpectrumMetric() = default;

protected:
    ISpectrumMetric() = default;
};

class LevelAdjustedMetric : public ISpectrumMetric
{
public:
    double evaluate(double const* bins, int const count) const override
    {
        return evaluate(bins, count, true);
    }

    virtual double evaluate(double const* bins, int const count, bool const applyOffset) const
    {
        double acc = 0.0;
        for (int i = 0; i < count; ++i) {
            acc += bins[i];
        }
        double const avg = acc / static_cast<double>(count);
        return applyOffset ? avg + levelOffset() : avg;
    }

private:
    virtual double levelOffset() const = 0;
};

class NarrowbandAnalyzer final : public LevelAdjustedMetric
{
public:
    double levelOffset() const override
    {
        return 0.1;
    }
};

// Default arguments are resolved using the static type of the pointer or reference.
// Calling through ISpectrumMetric const* will not see the three-argument overload unless
// you expose it virtually — this exercise keeps the footgun visible in comments instead.

// Name hiding vs override (illustrative only):
struct BaseTune
{
    virtual void tune(int bin) { (void)bin; }
};

struct DerivedTune : BaseTune
{
    void tune(double hz)
    {
        (void)hz;
    } // hides BaseTune::tune — not an override because the parameter type differs
};
Why these features: final stops risky further virtual tables on certified DSP paths. Default arguments on non-interface helpers illustrate why core contracts should stay in pure virtuals without defaults.
Exercise 7 — Integration

Context: Mono and stereo mixers accumulate PSD contributions for a dashboard.

Define class PsdContribution with protected double value_, explicit constructor, double value() const.

Derive class StereoPsdContribution : public PsdContribution holding double right_. Implement StereoPsdContribution operator+(StereoPsdContribution const& a, StereoPsdContribution const& b) as a non-member friend if needed to read privates, and PsdContribution operator+(PsdContribution const& a, PsdContribution const& b) for mono sums.

Ensure at least one operator is implemented with explicit left/right symmetry called out in comments. No STL containers.

Topics: operator overloading (left and right forms); inheritance; abstract/interface ideas optional.

class StereoPsdContribution;

class PsdContribution
{
public:
    explicit PsdContribution(double const value)
        : value_{value}
    {
    }

    double value() const
    {
        return value_;
    }

    friend PsdContribution operator+(PsdContribution const& a, PsdContribution const& b);

protected:
    double value_;
};

class StereoPsdContribution : public PsdContribution
{
public:
    StereoPsdContribution(double const left, double const right)
        : PsdContribution{left}
        , right_{right}
    {
    }

    double right() const
    {
        return right_;
    }

    friend StereoPsdContribution operator+(StereoPsdContribution const& a, StereoPsdContribution const& b);

private:
    double right_;
};

PsdContribution operator+(PsdContribution const& a, PsdContribution const& b)
{
    return PsdContribution{a.value_ + b.value_};
}

StereoPsdContribution operator+(StereoPsdContribution const& a, StereoPsdContribution const& b)
{
    // Symmetric sum: left channel uses base storage, right channel stored in derived field.
    return StereoPsdContribution{a.value_ + b.value_, a.right_ + b.right_};
}
Why these features: Free-function operator+ keeps symmetry for commutative PSD fusion. Friends remain narrowly scoped to avoid breaking invariants while reading both channels.
