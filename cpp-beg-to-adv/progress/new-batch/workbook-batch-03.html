Batch 3 — Classes: definition, encapsulation, constructors, multiple files, include guards, pointers, destructors

How to use this workbook: Several exercises describe a multi-file layout. You can still verify logic in a single file first, then split as instructed. Compile with all .cpp files together.

Subjects (in order): class definition → encapsulation (getters/setters) → constructors → split across files → include guards → managing objects via pointers → destructors.

The final exercise focuses on destructors and cleanup, using dynamic allocation from earlier topics.

Exercise 1Class definition

Task: Define a class Buffer with public: member int capacity; and public: member function bool empty() const that returns true when capacity == 0. Write a short main that creates Buffer b{0}; and checks b.empty().

  • Use aggregate-style init or a constructor—your choice—but empty() must be const.
class Buffer {
public:
    int capacity{0};
    bool empty() const { return capacity == 0; }
};

int main() {
    Buffer b{0};
    return b.empty() ? 0 : 1;
}

Exercise 2Encapsulation

Task: Redesign Counter with private int value_. Provide public int get() const, void set(int v), and void increment(). Do not expose value_ directly.

class Counter {
    int value_{0};
public:
    int get() const { return value_; }
    void set(int v) { value_ = v; }
    void increment() { ++value_; }
};

Exercise 3Constructors

Task: Class Sample with default constructor that sets a private id_ to 0, and a constructor taking int id that sets id_. Add int id() const. Demonstrate both constructions in main.

class Sample {
    int id_{};
public:
    Sample() : id_(0) {}
    explicit Sample(int id) : id_(id) {}
    int id() const { return id_; }
};

int main() {
    Sample a;
    Sample b{42};
    return b.id() - a.id();
}

Exercise 4Multiple files

Task: Describe (and implement locally if you prefer) a split: Widget.h declares class Widget with void poke();, Widget.cpp defines void Widget::poke() { }, main.cpp includes Widget.h and calls poke(). List the exact compiler command you would use for two .cpp files.

  • Clarity matters: show #include "Widget.h" in .cpp files.
// Widget.h
#pragma once
class Widget {
public:
    void poke();
};

// Widget.cpp
#include "Widget.h"
void Widget::poke() {}

// main.cpp
#include "Widget.h"
int main() {
    Widget w;
    w.poke();
    return 0;
}

// Example (GCC/Clang): g++ -std=c++20 -Wall -Wextra -pedantic main.cpp Widget.cpp -o app
// Example (MSVC): cl /EHsc /std:c++20 main.cpp Widget.cpp

Exercise 5Include guards

#ifndef WIDGET_H

class Widget {
public:

Exercise 6Pointers to objects

Task: Dynamically allocate a Counter (from your encapsulation pattern) with new, call increment() through the pointer, read get(), then delete the pointer. Use Counter* explicitly.

  • Every new must match one delete.
class Counter {
    int value_{0};
public:
    int get() const { return value_; }
    void increment() { ++value_; }
};

int main() {
    Counter* p = new Counter();
    p->increment();
    int v = p->get();
    delete p;
    return v == 1 ? 0 : 1;
}

Exercise 7Destructors

Task: Class Owner holds int* data_ allocated in the constructor with new int(7). Implement a destructor that deletes data_. Rule of zero/three/five: for this drill, implement destructor only and delete copy constructor and copy assignment (= delete) to avoid double-free. Add accessor int value() const reading *data_.

  • Emphasis: destructor runs when object goes out of scope or is deleted.
class Owner {
    int* data_{nullptr};
public:
    Owner() : data_(new int(7)) {}
    ~Owner() { delete data_; }

    Owner(const Owner&) = delete;
    Owner& operator=(const Owner&) = delete;

    int value() const { return *data_; }
};
