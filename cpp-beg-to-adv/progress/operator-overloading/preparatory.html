C++ Operator Overloading – Complete Workbook

1. Foundations – What is Operator Overloading?

Operator overloading allows you to define how operators behave for your own types. 

Complex a, b;
a + b; // You define what this means
Operators are just functions: 
a + b  →  operator+(a, b)

2. Left vs Right Operand – Critical Concept

2.1 Member Operator

class A {
public:
    A operator+(const A& other) const;
};

This means: 

a + b  →  a.operator+(b)
  • Left operand → object calling the function
  • Right operand → parameter
---

2.2 Non-Member Operator

A operator+(const A& a, const A& b);

Now: 

a + b → operator+(a, b)
  • Both operands are equal
  • No "owner" object
---

2.3 Why This Matters

Consider: 

int + MyClass
❌ Member version cannot handle this ✔️ Non-member can

4. Inheritance + Operator Overloading

4.1 Base Class Operator

class Base {
public:
    Base operator+(const Base& other) const;
};

4.2 Derived Class

class Derived : public Base { };

✔️ Derived inherits operator+ ❗ But:

  • No polymorphism
  • Returns Base
  • May lose Derived info
This is one of the biggest pitfalls in C++

6. Why Operators Are NOT Polymorphic

Operators are just functions: 

operator+(a, b)

And:

  • Functions are not virtual unless declared virtual
  • Non-member operators cannot be virtual

Therefore:

No runtime polymorphism

7. The Professional Solution (Important)

7.1 Virtual Hook Pattern

class Base {
public:
    virtual Base* add(const Base& other) const = 0;
};

7.2 Operator Delegation

Base* operator+(const Base& a, const Base& b) {
    return a.add(b);
}
Same idea as your StreamingInterface!

11. Final Mental Model

  • Operators are functions
  • Member operator → left operand is special
  • Non-member → symmetric
  • No polymorphism unless using virtual delegation
  • Inheritance does NOT mean override
If you master this, you now understand one of the most misunderstood parts of C++.
