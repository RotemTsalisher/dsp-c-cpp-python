C++ Interfaces – From Absolute Beginner to Expert

1. The Big Picture – Why Interfaces Exist

Before jumping into syntax, we need to understand the problem interfaces solve.

Imagine you're writing a program with different types of objects:

  • Cars
  • People
  • Robots

You want ALL of them to be printable using: 

std::cout << object;

But each one prints differently.

So the question becomes:

How do we force all classes to support printing in a consistent way?

That’s exactly what an interface solves.

Mental Model:
An interface is like a contract:
"If you inherit from me, you MUST implement these functions."

2. Core Concepts (Deep Understanding)

2.1 What is Polymorphism?

Polymorphism means:

"Same interface, different behavior."

Example: 

Shape* s = new Circle();
Shape* s2 = new Rectangle();

Both are treated as Shape, but behave differently.

2.2 Virtual Functions (What REALLY happens)

virtual void func();

This tells the compiler:

  • "Do NOT decide which function to call at compile time"
  • "Wait until runtime (dynamic dispatch)"
Under the hood, this is implemented using a vtable (virtual table).

2.3 Pure Virtual Functions

virtual void func() = 0;

This means:

  • No implementation exists
  • Derived classes MUST implement it
  • The class becomes abstract

2.4 Abstract Classes

A class with at least one pure virtual function: 

class Animal {
public:
    virtual void speak() = 0;
};

You cannot do: 

Animal a; // ❌ ERROR

3. Your Code – Deep Breakdown

#ifndef __STREAMINGINTERFACE__H
#define __STREAMINGINTERFACE__H

#include <iostream>

class StreamingInterface {
    friend std::ostream& operator<<(std::ostream& os, const StreamingInterface& si);

public:
    virtual void stream_insert(std::ostream out) const = 0;
};

#endif

3.1 Include Guards (Why they matter)

Prevent multiple inclusion of the same header.

Without them → linker errors / duplicate definitions.

---

3.2 Why This Class is an Interface

  • Contains a pure virtual function
  • No implementation
  • Defines behavior but not logic

Therefore:

It is an interface.

---

3.3 The Pure Virtual Function

virtual void stream_insert(std::ostream out) const = 0;

This enforces:

  • Every derived class MUST define how it prints itself
  • Ensures consistency across all derived types
Critical Bug:
This should be: 
std::ostream& out
Why?
  • Streams cannot be copied
  • Passing by value breaks behavior
---

3.4 The Friend Operator

friend std::ostream& operator<<(std::ostream& os, const StreamingInterface& si);

This is the key design trick.

It allows: 

std::cout << obj;

But instead of implementing it separately for each class:

We centralize the logic.

---

3.5 How It Works Together

std::ostream& operator<<(std::ostream& os, const StreamingInterface& si) {
    si.stream_insert(os);
    return os;
}

Flow:

  1. You call: std::cout << obj;
  2. Operator<< is invoked
  3. It calls stream_insert
  4. The correct derived implementation runs (polymorphism)
This is a classic example of: Runtime polymorphism + interface enforcement

4. Full Working Example

class Person : public StreamingInterface {
    std::string name;

public:
    Person(std::string n) : name(n) {}

    void stream_insert(std::ostream& out) const override {
        out << "Person: " << name;
    }
};

Usage: 

Person p("Rotem");
std::cout << p;

What happens internally:

  • operator<< is called
  • stream_insert() is dispatched via vtable
  • Correct implementation runs

5. Under the Hood (Expert Level)

5.1 vtable Mechanism

Each class with virtual functions has:

  • A vtable (table of function pointers)
  • A hidden pointer inside objects → vptr

At runtime:

  • The object’s vptr points to its class vtable
  • The correct function is selected dynamically

5.2 Why This Matters

  • Enables polymorphism
  • Allows interface-based design
  • Used everywhere in large systems

6. Design Pattern Insight

This pattern is known as:

"Interface + Non-member operator"

Why it's good:

  • Separation of concerns
  • Reusable operator<<
  • Cleaner design

7. Common Mistakes (Very Important)

  • ❌ Passing ostream by value
  • ❌ Forgetting = 0
  • ❌ Not marking override
  • ❌ Trying to instantiate abstract class
  • ❌ Forgetting virtual destructor (advanced)
