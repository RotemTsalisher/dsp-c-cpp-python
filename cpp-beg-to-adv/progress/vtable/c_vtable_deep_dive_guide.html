C++ VTable — Complete Deep Dive (Beginner to Expert)

Step 1: What Problem Does the VTable Solve?

When using virtual, C++ must decide at runtime which function to call.

This requires a mechanism to map an object → correct function implementation.

The vtable is essentially a lookup table:
  • Input: object
  • Output: correct function address

Step 2: What is a VTable?

A vtable (virtual table) is a hidden array of function pointers.

Base vtable:
[ &Base::f ]
[ &Base::g ]

Each class with virtual functions has its own vtable.

Step 3: The vptr (Virtual Pointer)

Every object of a polymorphic class contains a hidden pointer called vptr.

Object:
[ vptr ] → points to vtable
[ data members ]
Think of vptr as the object's "type identity at runtime".

Step 4: How Objects Get Their vptr

The compiler inserts code into constructors:

Derived::Derived() {
    this->vptr = &Derived_vtable;
}
Important:
  • vptr is set during construction
  • Changes during base → derived construction phases

Step 5: Function Call Through VTable

A virtual call:

obj->f();

Becomes roughly:

obj->vptr[0](obj);
This is dynamic dispatch in action.

Step 6: Inheritance and VTable Overriding

Derived classes override entries in the vtable.

Base vtable:
[ &Base::f ]

Derived vtable:
[ &Derived::f ]
Only overridden functions are replaced.

Step 7: Multiple Virtual Functions

class Base {
    virtual void f();
    virtual void g();
};

VTable:
[ &Base::f ]
[ &Base::g ]

Step 8: Multiple Inheritance

Each base class may introduce its own vtable and vptr.

Leads to complex layouts and pointer adjustments.

Step 9: Constructor Behavior

During construction:

  • Base constructor runs first
  • vptr points to base vtable
  • Then updated to derived
Virtual calls inside constructors use base version!

Step 10: Destructor Behavior

During destruction:

  • vptr changes back step-by-step
  • Derived destroyed first
  • Then base

Step 11: Memory Cost

  • +1 pointer per object
  • Shared vtable per class

Step 12: Compiler Perspective

The compiler transforms virtual calls into indirect calls via vtable.
