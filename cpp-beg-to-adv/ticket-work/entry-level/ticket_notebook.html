VoiceLink Core (VLC) — how to work a ticket

System: Embedded voice uplink for a duplex intercom. 48 kHz PCM, stereo-to-mono mix, ADC scaling helpers, mic gain chain, and a small heap-backed PSD buffer.

Your job: Each ticket describes one defect already present in the codebase. Patch only the files listed under Fix, then re-run that ticket’s test until it prints PASS.

Code: ../vlc-core-system/ · Build & test once:

cd ../vlc-core-system
cmake -S . -B build
cmake --build build --target vlc_ticket_test
.\build\Debug\vlc_ticket_test.exe VLC-ENTRY-101

List every ticket id: .\build\Debug\vlc_ticket_test.exe --list

VLC-ENTRY-101 P3 · Minor Field soak

Mono mix sounds 6 dB hot on uplink

Problem

When left and right carry the same tone, uplink mono RMS is about 6 dB above the lab reference. The downmix doubles correlated energy instead of preserving it.

Fix (bug is here)

src/mono_mix.cpp — function mono_mix_down (alias monoMixDown in include/vlc/mono_mix.hpp).

Reproduce

.\build\Debug\vlc_ticket_test.exe VLC-ENTRY-101

Bug output (before fix):

observed mono_mix_down(0.2, 0.2): 0.4
expected mono_mix_down(0.2, 0.2): 0.2
Pass criteria: Test prints VLC-ENTRY-101 PASS and exit code 0.
Hint: For equal L and R, what factor on (L + R) keeps amplitude unchanged?

Root cause: Summing without the 0.5 coefficient doubles amplitude for correlated signals.

return 0.5 * (left + right);
VLC-ENTRY-102 P3 · Minor Bench

ADC full-scale mapping reads 2× high

Problem

12-bit ADC counts are converted to volts with the wrong full-scale denominator. A 1.25 V input reads about 2.5 V on the bench.

Fix (bug is here)

src/adc_counts.cpp — counts_to_volts (alias countsToVolts).

Reproduce

.\build\Debug\vlc_ticket_test.exe VLC-ENTRY-102
observed counts_to_volts(2047, 2.5, 12): 2.49878
expected counts_to_volts(2047, 2.5, 12): 1.25
Pass criteria: VLC-ENTRY-102 PASS
Hint: Unipolar 12-bit full scale is code 2^12 - 1, not 2^11.
double const denom = std::ldexp(1.0, bits) - 1.0;
return (counts / denom) * fullScaleVolts;
VLC-ENTRY-103 P2 · Major Long-run soak

PSD soak test leaks memory

Problem

HeapBins allocates with new[] in the constructor but never releases the buffer. Long soak runs climb RSS until the allocator fails.

Fix (bug is here)

src/heap_bins.cpp — destructor HeapBins::~HeapBins (class in include/vlc/heap_bins.hpp).

Reproduce

.\build\Debug\vlc_ticket_test.exe VLC-ENTRY-103
observed live_instances after scope: 1
expected live_instances after scope: 0
Pass criteria: VLC-ENTRY-103 PASS — live instance count returns to zero after the object is destroyed.
Hint: Every new[] needs a matching delete[] in the destructor.
~HeapBins() { delete[] bins_; }
