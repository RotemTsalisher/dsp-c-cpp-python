VLC-SR-301 P0 · Blocker Opened by QA · Soak + ASan

Random crash on teardown after loading third-party notch codec

Summary: Host HIL with ASan intermittently faults in delete plugin; where plugin is ICodec* pointing at a derived object with extra members. Steps: Load DLL-provided codec, run 10k init/teardown cycles. Expected: Clean shutdown. Actual: Heap corruption / invalid free. Component: struct ICodec — destructor not virtual.

Hint: Deleting through a base pointer without a virtual destructor is undefined behavior if the dynamic type has a non-trivial destructor or additional state.
struct ICodec
{
    virtual void encodeFrame(double const* frame, int count) = 0;
    virtual ~ICodec() = default; // was missing → UB on delete through ICodec*

protected:
    ICodec() = default;
};

struct NotchCodec final : ICodec
{
    void encodeFrame(double const*, int) override {}
    ~NotchCodec() override { /* release notch state */ }
};

Review note: Abstract class and pure virtual functions + polymorphic ownership—public API bases used for delete must have virtual ~I.

VLC-SR-302 P1 · Critical Opened by QA · Certification review

“Safety” DSP box reports wrong channel ID after refactor to value semantics

Summary: Telemetry uses Box idBox = FancyBox{}; then logs idBox.id() for routing. After refactor, Fancy path never appears in logs. Expected: Fancy identifier when constructed as FancyBox. Actual: Base identifier only. Component: telemetry.cpp + Box hierarchy (non-virtual API).

Hint: Slicing plus static binding: value-typed base object stores only the base subobject unless you use pointers/references or virtuals.
class Box
{
public:
    int id() const { return 1; }
};

class FancyBox : public Box
{
public:
    int id() const { return 2; }
};

// Wrong for polymorphic identity:
// Box idBox = FancyBox{}; idBox.id(); // → 1

// Fix: reference / pointer to complete object, or virtual id().
FancyBox fb{};
int const routed = fb.id(); // 2 — static binding on correct static type

// If polymorphic logging is required, introduce virtual id() + pointers/references.

Review note: Static Binding vs polymorphism—senior fix is either correct type for value semantics or redesign with virtual + pointers.

VLC-SR-303 P1 · Critical Opened by QA · A/B with golden FFT

Golden FFT harness disagrees with device when curve normalisation flag omitted

Summary: ICurve const* path calls eval(0.5) one-arg; harness expects default second argument norm=false on LabCurve override, but device applies true. Expected: Same numeric path as harness. Actual: Mismatch; audit shows default arguments bound at compile time to static type. Component: Curve::eval virtual with default parameter.

Hint: Default arguments are not “virtual”; they depend on the static type used at the call site. Prefer overload sets or a single parameter struct.
class ICurve
{
public:
    virtual double eval(double x) const = 0;
    virtual ~ICurve() = default;
};

class LabCurve : public ICurve
{
public:
    double eval(double const x) const override
    {
        return eval(x, false);
    }

    double eval(double const x, bool const norm) const
    {
        return norm ? x * 2.0 : x;
    }
};

// Call sites that go through ICurve* must use the one-arg virtual,
// not a defaulted second parameter on a static type-only overload.

Review note: virtual override w/ default args footgun—public polymorphic APIs should avoid defaulted parameters on split overloads; seniors split into explicit functions or flags structs.

VLC-SR-304 P1 · Critical Opened by QA · Stereo image collapse

Stereo PSD merge drops right channel after operator+ refactor

Summary: Free operator+ for StereoPsd summed left via base but read right_ through a non-friend path; shipping build zeroed right. Steps: Add two stereo bins, compare L/R. Expected: Both channels accumulate. Actual: Right stays zero. Component: stereo_psd.cpp

Hint: Free operator+ is not a member; it cannot read private right_ unless it is a friend or you use public accessors only.
class MonoPsd
{
public:
    explicit MonoPsd(double const e) : e_{e} {}
    double energy() const { return e_; }
protected:
    double e_;
};

class StereoPsd : public MonoPsd
{
public:
    StereoPsd(double const L, double const R) : MonoPsd{L}, r_{R} {}
    double right() const { return r_; }
    friend StereoPsd operator+(StereoPsd const& a, StereoPsd const& b);
private:
    double r_;
};

StereoPsd operator+(StereoPsd const& a, StereoPsd const& b)
{
    return StereoPsd{a.energy() + b.energy(), a.right() + b.right()};
}

Review note: operator overloading (left and right, inheritance)—friends or narrow public accessors; never assume private layout access from a free function.

VLC-SR-305 P0 · Blocker Opened by QA · Security + factory audit

Factory calibration friend can write base trim from unrelated TU (linker + access leak)

Summary: setFactoryTrim(CalAmp&, double) was declared friend inside CalAmp but defined in a TU that also tried to poke protected base members on a non-friend code path. Nightly build broke; even when it links, another engineer “helpfully” added using Base::trim_; in public for diagnostics. Expected: Trim writable only via audited friend; diagnostics build should not widen access in production defines. Actual: Access soup + fragile ODR story. Component: CalAmp, GainBase, factory TU.

Hint: Keep friend definitions adjacent to the class; remove using resurrections from production headers. If diagnostics need visibility, isolate behind #ifdef VLC_DIAGNOSTIC_BUILD and code review.
class GainBase
{
protected:
    double trim_{1.0};
};

class CalAmp : public GainBase
{
    friend void setFactoryTrim(CalAmp& a, double v);

public:
    double trim() const { return trim_; }
};

void setFactoryTrim(CalAmp& a, double const v)
{
    a.trim_ = v; // OK: friend of CalAmp may access protected base subobject
}

// Remove from shipping headers:
// class CalAmp : public GainBase { public: using GainBase::trim_; };

Review note: friend in inheritance + resurrect members in a more relaxed access level—senior work is policy: who may touch trim_, and never accidentally exporting protected state in release.
