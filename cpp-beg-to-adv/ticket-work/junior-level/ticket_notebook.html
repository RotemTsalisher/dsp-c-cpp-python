VLC-JR-201 P2 · Major Opened by QA · CI fuzz

quantizeSample<T> instantiates for user-defined types and corrupts bins

Summary: Fuzz harness passed a small POD struct BinTag { int x; } into quantizeSample; build succeeded and garbage landed in PSD path. Expected: Compile-time rejection for non-arithmetic T. Actual: Template accepts anything. Component: dsp/quantize.h

Hint: Add a C++20 requires (or a concept) tied to std::is_arithmetic_v<T>.
#include <type_traits>

template <typename T>
requires std::is_arithmetic_v<T>
constexpr T quantizeSample(T const v, T const step)
{
    T const q = v / step;
    return static_cast<T>(static_cast<int>(q)) * step;
}

Review note: requires + function templates—narrows the API surface before fuzz can drive invalid types in.

VLC-JR-202 P1 · Critical Opened by QA · Stress HIL

Intermittent garbage in uplink PSD summary after telemetry thread lands

Summary: Main thread reads summary double immediately after starting worker; ~1% runs show stale or torn values. Steps: Spawn thread writing summary, main reads without synchronization (intentional minimal repro). Expected: Join worker before read, or document single-writer contract (here: fix join). Actual: Missing join() in one code path. Component: TelemetrySlice::runOnce()

Hint: std::thread destructor calls std::terminate if still joinable—always pair start with join (or a documented policy).
#include <thread>

void runOnce(double& summary)
{
    std::thread worker([&summary]() {
        summary = 0.125; // model slow PSD slice integration
    });
    worker.join();
}

Review note: threads (<thread> basics)—lifetime of summary must extend past join(); here reference capture is OK because caller blocks until join completes.

VLC-JR-203 P2 · Major Opened by QA · Plugin SDK

Third-party notch filter registered as Source* always returns silence

Summary: Vendor ships NotchSource : public Source. Factory stores pointer as Source* and calls next(). Notch path never runs. Expected: Dynamic dispatch into NotchSource::next(). Actual: Base Source::next() always executes. Component: class Source declaration

Hint: Without virtual, the call resolves statically to the base type.
class Source
{
public:
    virtual double next() { return 0.0; }
    virtual ~Source() = default;
};

class NotchSource : public Source
{
public:
    double next() override { return 0.1; }
};

Review note: Virtual keyword and Polymorphism / Inheritance and Method Overriding—extension points for DSP sources must be virtual.

VLC-JR-204 P2 · Major Opened by QA · HAL review

Register write helper accepts 16-bit field and corrupts AFE word

Summary: maskedOr(word, mask, field) compiled when field was std::uint16_t, shifted garbage into upper bits after promotion. Expected: Only 32-bit register words accepted at compile time. Actual: Too-generic template. Component: dsp::afe::maskedOr

Hint: Combine a variable-template trait (is_word32_v) with a concept so only std::uint32_t fields compile.
#include <cstdint>
#include <type_traits>

namespace dsp::afe
{
template <typename T>
inline constexpr bool is_word32_v = std::is_same_v<T, std::uint32_t>;

template <typename T>
concept Word32 = is_word32_v<T>;

template <Word32 T>
constexpr std::uint32_t maskedOr(std::uint32_t const base, std::uint32_t const mask, T const field)
{
    return base | (static_cast<std::uint32_t>(field) & mask);
}
}

Review note: traits via variable templates + concepts—mirrors how HAL reviews block accidental widths.

VLC-JR-205 P1 · Critical Opened by QA · Release gate

Comb-delay tap energy gate never trips (always passes audio)

Summary: QA passes double (*pred)(double) into gateTap but the engineer stored a capturing lambda in a temporary and tried to decay it to function pointer—build hack forces wrong predicate. Expected: Stable function pointer to a named predicate with explicit signature. Actual: Undefined behavior / wrong linkage in integration branch. Component: gateTap(double x, bool (*p)(double))

Hint: Capturing lambdas cannot become plain C function pointers—use a free function or a static non-capturing lambda assigned to a named bool (*)(double).
using TapPred = bool (*)(double);

bool overNoiseFloor(double const x)
{
    static constexpr double floor = 1e-5;
    return x > floor;
}

bool gateTap(double const x, TapPred pred)
{
    return pred(x);
}

bool demo(double const x)
{
    return gateTap(x, &overNoiseFloor);
}

Review note: function pointers + passing functions as arguments—DSP gates in bare-metal code paths often require explicit function pointer ABI, not ad-hoc lambda decay.
