EXERCISE 4: Compound Requires Expressions
Difficulty: Intermediate

Objective:
Master compound requirements, checking return types, and using multiple constraints in requires expressions.

Requirements:
1. Create a concept `Subtractable` that checks:
   - Type supports `-` operator
   - The result of subtraction is convertible back to the same type
   - Use compound requirement: `{ a - b } -> std::convertible_to<T>`

2. Create a concept `Incrementable` that checks:
   - Type supports prefix `++` operator
   - Type supports postfix `++` operator
   - Both operations return appropriate types

3. Create a concept `ArithmeticOperations` that checks if a type supports:
   - Addition (`+`)
   - Subtraction (`-`)
   - Multiplication (`*`)
   - Division (`/`)
   - All in a single requires expression using semicolons

4. Create a function template `safeDivide()` that:
   - Takes two parameters of type `T`
   - Uses a requires clause to ensure:
     a) Type supports division (`/`)
     b) Division result is convertible to `double`
   - Returns the quotient as a double

5. Create a concept `PointerLike` that checks if a type:
   - Supports dereference `operator*()`
   - The result of dereference is not void

6. Create a function template `dereference()` that:
   - Takes a pointer-like type
   - Uses `PointerLike` concept
   - Returns the dereferenced value
   - Test with `int*`, `double*`, etc.

7. Create a concept `ArrayAccessible` that checks if a type can be subscripted:
   - Has `operator[]` that takes an integral index
   - Use: `requires(T t, size_t i) { t[i]; }`

8. In your `main()` function:
   - Test `safeDivide()` with integers and doubles
   - Test `dereference()` with various pointer types
   - Create a C-style array and test array access concepts
   - Demonstrate compound requirements working

Example Output:
Safe divide 15 by 3: 5.0
Safe divide 10 by 4: 2.5
Dereference pointer to 42: 42
Array element at index 2: 30

Note:
- Explore compound requirement syntax: `{ expr } -> Concept<Type>` or `{ expr } -> std::convertible_to<Type>`
- Understand the difference between:
  - Simple requirement: `expr;` (just checks if valid)
  - Type requirement: `typename T::type;` (checks nested type exists)
  - Compound requirement: `{ expr } -> Type` (checks expression AND return type)
- Practice combining multiple checks in one requires expression
- Learn that `requires (T t) { ... }` lets you name variables for readability
